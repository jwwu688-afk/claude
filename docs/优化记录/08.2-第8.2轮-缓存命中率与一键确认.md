## 一、缓存命中：从"8640"到"78%"

### 1.1 为什么要改

状态行原来长这样：

```
⎿ 上下文 4.3% · 花费 $0 · 缓存命中 8640
```

8640 这个数字没有参照系。它可能是 20 万输入里的 4%（缓存基本没用），也可能是 1 万输入里的 86%（缓存很好）。用户每次都要自己心算——**需要用户心算的指标等于没显示**。

改成百分比之后：

```
⎿ 上下文 4.3% · 花费 $0.02 · 缓存命中 78%
```

一眼就能判断"我是不是在白付原价"。

### 1.2 分母不能随手取

这是唯一有技术含量的地方。两家对 `prompt_tokens` 的定义不一样：

| 厂商 | 字段 | 含义 |
|---|---|---|
| OpenAI 系 | `prompt_tokens` | **已包含**缓存命中的部分 |
| Anthropic 系 | `input_tokens` | **不包含**缓存读写，真正喂进去的是 `input + cache_read + cache_creation` |

如果统一拿 `prompt_tokens` 当分母，Anthropic 口径下 `input=2000`、`cache_read=8000` 会算出 **400%**——屏幕上真会显示"缓存命中 400%"。

判据是：带 `prompt_tokens_details` 对象的是 OpenAI 口径，带 `cache_read_input_tokens` 的是 Anthropic 口径。

```python
if details is not None:                 # OpenAI
    total_input = prompt_tokens
elif cache_read or cache_creation:      # Anthropic
    total_input = prompt_tokens + cache_read + cache_creation
else:
    total_input = prompt_tokens

total_input = max(total_input, cached)  # 兜底：别让分母小于分子
```

最后那行兜底是给"只报 cached、不报 prompt_tokens"的中转站准备的。宁可显示 100%，也不能显示 300%。

### 1.3 按累计量算，不按最后一次

`_cached_tokens` / `_prompt_tokens` 都是会话级累加。如果只取最后一次请求，用户中间跑一次不带缓存的小请求，状态行就会从 80% 突然掉到 0%，看起来像"缓存失效了"，其实是视角问题。

## 二、授权：一次回车

### 2.1 改前

```
🤖
Please confirm if you want to execute the tool call:  Tool: task, args: {'description': '回复用户的问候', 'prompt': '用户向你打招呼说"你好"。请用 task 工具启动 greeting-responder agent。', 'subagent_type': 'general-purpose'}
Answer yes or no, if refusing please provide a reason
> 
```

三个问题叠在一起：整段英文、整个参数字典原样铺开、必须打 `yes` 才算同意。而且判断用的是 `"yes" in text` —— 输入 **`yesterday`** 里含 `yes`，命令就会被执行。这是误放行，不是误拒。

### 2.2 改后

```
⏺ cmd_runner(dir /s)
  ? 是否执行？  回车确认 · 输入 n 拒绝 · 或直接说你想怎么改
  > 
  ⎿  a.py b.py
```

规则只有三条，谁都能记住：

| 输入 | 结果 |
|---|---|
| 直接回车（或只有空格） | 按默认值走。当前默认同意 → **执行** |
| `y` / `yes` / `是` / `确认` / `ok` … | 执行 |
| `n` / `no` / `否` / `取消` … | 不执行 |
| 其他任何内容 | 不执行，**并把这句话当作"我想怎么改"交给模型** |

第四条是最有用的一条。用户想说"别删这个文件，用 file_edit"时，一句话说完就完事，不用先选 no、再等系统单独问一遍理由——少一次往返。这也是 Claude Code 的语义：除了同意，剩下的输入都是反馈。

### 2.3 为什么默认同意是安全的

这是本轮唯一需要斟酌的设计。默认同意意味着"手滑回车 = 执行"，看起来和"安全优先"矛盾。三点理由：

1. **信息在提问之前就给全了。** `⏺ cmd_runner(dir /s)` 就在上面一行，参数不再是一坨字典，而是压缩过的一行摘要。用户看到命令再决定，不是盲按。
2. **这就是 Claude Code 的行为。** 它的权限对话框里按回车等于选第一项"Yes"。
3. **真正的安全网不在这里。** 靠"默认拒绝"挡不住 `rm -rf`——用户会习惯性地打 y。能挡住的是规则引擎（白名单/黑名单/路径边界），那是第 9 轮。

接口已经把 `default_yes` 留出来了：高危操作传 `False`，回车就变成"拒绝"，必须打 `y` 才放行。第 9 轮不用再改签名。

### 2.4 顺带修掉的三处

| # | 问题 | 改法 |
|---|---|---|
| 1 | 同一个命令在屏幕上出现两次：先 `Tool: xxx, args: {...}` 提问，同意后再 `⏺ xxx(...)` | 头部提前到提问之前画一次；`_execute_tool` 加 `show_header=False` 不再重画 |
| 2 | 文件类工具的参数预览是整个字典（`file_edit({'path': ..., 'new_string': '...'})`），`new_string` 几百行时直接刷屏 | `_args_preview` 补 `path` / `pattern` 两类，`file_edit` 只显示路径 |
| 3 | 被拒绝之后屏幕上什么都没有，用户不知道那一下有没有生效 | 新增 `tool_denied()`，补一行 `⎿ 已拒绝：<理由>` |

第 2 条的实际效果（改前 → 改后）：

```
file_edit({'path': 'a.py', 'old_string': 'hi', 'new_string': 'bye\nbye\n...'})
→ file_edit(a.py)
```

## 三、真机数据（2026-11-06 15:40，已授权）

两次**完全相同前缀**的请求（系统提示词 2 463 字符 + 一句提问），模型 `spark-x2.6`：

| 请求 | prompt_tokens | prompt_tokens_details | 累计命中率 |
|---|---|---|---|
| 第 1 次（冷启动） | 1427 | `null` | 0.0%（0/1427） |
| 第 2 次（命中） | 1427 | `{"cached_tokens": 1408, "audio_tokens": null}` | **49.3%**（1408/2854） |

三个结论：

1. **口径猜对了。** 这个接口是 OpenAI 口径：`prompt_tokens` 已包含缓存部分，分母直接用它是正确的。单次命中 1408/1427 = 98.7%，说明缓存确实在生效。
2. **`prompt_tokens_details` 会整体为 `null`。** 冷启动那次不是"字段里 cached_tokens=0"，而是整个对象不存在。代码里用的是 `if details is not None` 而不是 `if details.cached_tokens`，正好不会在 None 上取属性——这条是被真实数据验证的，不是假设。
3. **会话级累计值会明显低于单次值。** 两次请求显示 49.3%，而不是 98.7%，因为第一次冷启动把平均值拉下来了。这正是"你实际付了多少钱"的真实刻画：缓存省下的钱是相对"全部输入"而言的，冷启动那次一分没省。

顺带一个环境事实：`.env` 里 `ENABLE_PROMPT_CACHE=0`，也就是第 6 轮做的 `cache_control` 断点在这家服务上根本没打开——但缓存**照样命中**，因为服务端自己做前缀缓存，不需要客户端标记。所以那个开关在本项目当前配置下是空转；它仍然有意义，只是只在 Anthropic 原生接口上才需要。
