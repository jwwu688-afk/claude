# 第 33 轮：四档工作模式（default / plan / accept / auto）

2026-11-12。版本 0.10.2 → 0.11.0。

## 一句话

给工具调用加了一层"模式"：同一个 `classify()`，在四档下给出四种结论；`plan` 和 `auto` 真正改变的是**工具面**，不只是"要不要弹窗"。

## 为什么要做

在这之前，权限只有两个结果：问，或者不问。这在一个只会"改文件、跑命令"的 agent 里够用，但有三种真实需求它表达不了：

| 场景 | 旧行为的问题 |
|---|---|
| 想让它先调研、出方案，别动手 | 只能靠提示词求它"先别改"，而它随时可以调 `file_write` |
| 改十个文件、每次都要回车 | 十个确认框，节奏全断 |
| 明确知道自己要什么，不想被打断 | 没有"全放开"这一档，只能看着它一条条问 |

第 9 轮的注释里写过"完整的权限引擎留给第 10 轮"，`docs/ROADMAP.md` 也早把 Plan mode 列在 P1。这一轮把这三件事一起做了，因为它其实是同一个东西：**模式是对基础判定的过滤器**。

## 四档

| 档位 | 底栏 | 颜色 | 语义 |
|---|---|---|---|
| `default` | 默认模式 | 灰 | 每个写操作、每条命令都要确认（第 9 轮的行为，一字未改） |
| `plan` | 计划模式 | 浅绿 | 只能读和查，产出方案 |
| `accept` | 接受编辑 | 紫 | `file_write` / `file_edit` 直接执行，命令仍要确认 |
| `auto` | 自动模式 | 金黄 | 全部直接执行，不再询问 |

循环顺序 `default → plan → accept → auto`：从标准状态出发，先收紧到只读，再放开到能改文件，最后全放开。四档像一把开关沿一个方向推到底，按 Shift+Tab 不用记"刚才从哪来"。

`auto` 对应 Claude Code 的 `bypassPermissions`（那一档默认不在循环里）；`accept` 对应 `acceptEdits`；`plan` 同 Claude Code 的 plan mode；`default` 就是它的 default / manual。

## 判定：从两态到三态

`Decision.need_approval: bool` 换成 `Decision.action: allow | ask | deny`。

为什么必须换：加模式之后，"不问"分成两种完全不同的情况——**放行**和**拒绝**。用一个 `False` 表示不了拒绝，调用方会当成"可以执行"，这是把安全判断挤进一个布尔值的典型错误。

`need_approval` 保留成 property（`== action == "ask"`），所以 `conversation.py` 里原有的三处判断一行没改。

判定拆成两层：

```
base = _classify_base(tool, args)      # 第 9 轮那套规则，原样抽出
default → base
plan    → 只读/查询 allow，其余 deny
accept  → base 是 ask 且 tool ∈ WRITE_TOOLS → allow
auto    → 全部 allow（连危险规则都不参与）
```

分层的理由：模式是"策略"，危险规则是"底线"。混在一起写，以后加第五档就得在二十条正则中间找位置，改错一条就是安全事故。现在加一档只需在 `_apply_mode` 里加一个 `if`。

## 三处必须一起改，缺一处模式就是假的

1. **清单层**：`_get_available_tools()` 在 plan 下把 `allow` 收成 `PLAN_TOOL_ALLOWLIST`（只读 + `task` + `cmd_runner`）。模型连 `file_write` 长什么样都看不到。
2. **执行层**：`_is_tool_allowed()` 里加模式闸。清单层只是"看不到"——模型有记忆，可能凭上一轮清单或训练习惯硬写出工具名。
3. **子 agent 取交集**：plan 下派 `general-purpose`，它自带写权限，等于从侧门绕过只读。所以 `allow = 父允许集 ∩ agent.tools`。

第 3 条最容易漏，也最隐蔽：它不报错，只是在某天发现"计划模式把文件改了"。

`cmd_runner` 在 plan 下保留在清单里，因为调研要看 `git status` / `git log`。具体哪条能跑由 `is_query_command()` 逐条判：按 `|` 拆段、每段都要在查询白名单里，且不能出现 `>`、`>>`、`&&`、`;`、`$(`。

为什么不复用 `is_safe_command()`：那份表的目的是"默认模式下连问都不问"，刻意做得极窄；plan 要的是"只要不写盘就允许"，`git log | head`、`git blame` 都得能用。两份白名单、两个用途，混用会把正常调研全挡掉。

## 界面

- **底栏**：写死的"默认模式"换成当前档位，`▸▸` 和名字用该档颜色。重画时机选在"每次画横线"（`_draw_rule`）——那个时机天然存在，不需要在输入行渲染中途硬插内容。
- **配色两套**：`theme.MODE_COLORS` 给 rich（底栏），`theme.MODE_ANSI` 给裸转义码（快捷键提示）。两者不能互转，只能各存一份；都写在 theme.py 里，保证只有一处出处。
- **`/mode`**：不带参数列四档并上色，带参数直接切。这是 100% 可靠的入口。
- **快捷键**：Shift+Tab（`\x1b[Z`）+ Alt+T（`\x00t`）双路。conhost 不启用 VT 输入时 Shift+Tab 可能是 `\t`，和补全键撞车，所以必须有第二条路。

## 提示词：为什么当前模式不能进系统提示词

系统提示词在请求最前面，改一个字整段前缀缓存失效——`/cost` 里的命中率会直接掉下来，而模式是用户随时会切的东西。

所以拆成两半：

- 系统提示词里只放 `MODE_SECTION`：**固定**说明"有哪四档"，任何模式、任何时刻都一样；
- 当前档位由 `mode_reminder()` 附在每轮工具结果的尾部（和 todo 提醒同一段位置），另外切换时把提示拼进下一条 user 消息的第二个内容块。

## 踩到的三个坑

1. **用例写成 `{case: action}` 直接 TypeError**：case 里的 args 是 dict，不可哈希。改成"并列列表 + zip"。
2. **把 `\x1b[Z` 压回预读队列时顺序写反了**：先 append `"Z"` 再 append `"["`，弹出就是 `"Z["`。测试里那条"无回调时退化为按普通字符处理"抓到的，期望 `"[Z"`。
3. **Alt+M 撞上 `EXT_RIGHT = "M"`**：方向键右键的第二字节就是 `M`，Alt+M 会把"切模式"变成"光标右移"。改用 `Alt+T`（toggle），不和任何 `EXT_*` 常量冲突。

## 验证

- 新增 `test/test_modes.py`：80 项，覆盖四档循环、别名归一、4×7 判定矩阵、查询命令边界（12 条正例/反例）、清单白名单、reminder 文案、快捷键不丢输入。
- 既有四份测试全绿（42 + 37 + 52 + 23 项）。
- 裸对象集成检查：plan 下 `_is_tool_allowed("file_write")` 为 False、`file_read`/`cmd_runner` 为 True；模式提示拼成第二个内容块且取出即清空。
- **没有做的事**：没有启动真实对话，也没有调用任何模型接口——判定和快捷键都是纯函数，可以在不花钱的前提下验完。真机上的底栏配色和 Shift+Tab 是否被终端下发成 `\x1b[Z` 仍需手动看一眼。

## 未做 / 下一步

- **plan 模式没有"批准"工具**。Claude Code 用 `ExitPlanMode` 让用户批准方案后自动切档；这里第一版让用户自己按 Shift+Tab 或 `/mode`。加一个工具会让工具清单变一次、缓存再失效一次，收益要等真用一段时间再判断。
- **模式不落盘**：`/resume` 恢复会话后回到 default。要不要记住上次的档位，取决于实际使用习惯，先不做。
- **`accept` 没有"记住这个文件"**：Claude Code 在 acceptEdits 下有会话级的允许清单。那属于权限引擎的第二批（用户自定义规则），不在本轮。


## 补记（33.1）：Shift+Tab 在 conhost 上不生效

版本 0.11.0 → 0.11.1。真机第一晚就暴露了：按 Shift+Tab 只听到一声响铃，模式没切。

**根因不在代码，在控制台。** conhost 传统模式下，Shift+Tab 和 Tab 送给 `msvcrt.getwch()` 的都是同一个 `\t`（0x09）——"按没按 Shift"这件事在字符流里根本不存在。于是按键走进 `_handle_tab`，发现输入为空、没有候选，按第 16 轮的老逻辑响一声。用户看到的就是"没反应，还响"。

三条路摆在这里：

| 方案 | 结果 |
|---|---|
| 启用 `ENABLE_VIRTUAL_TERMINAL_INPUT` | 能让终端下发 `\x1b[Z`，但方向键会从 `\xe0H` 变成 `\x1b[A`，第 18 轮那套两字节解码全部失效。为一个快捷键改掉整个输入层的按键协议，风险不成比例 |
| `ReadConsoleInput` 读 `dwControlKeyState` | 能拿到 `SHIFT_PRESSED`，最准确，但要把 LineEditor 从"读字符"改成"读事件"，等于重写输入层 |
| **换判据（采用）** | Tab 只在 `/` 开头时有补全语义，其余情况它本来就是个无效操作（响铃）。把无效操作改成切模式，成本为零，而 Shift+Tab 在任何终端上都等效于 Tab |

代价：输入中文时误按 Tab 会切模式。概率低，再按一次就转回来。

验证：`test_modes.py` 从 80 项加到 **86 项**，新增"空输入按 Tab 切模式""Tab 不丢已输入内容""`/cos` 按 Tab 仍是补全不是切模式"三条；全量仍绿。`--version` = 0.11.1。


## 补记（33.2）：把"日志"改成"状态"

版本 0.11.1 → 0.11.2。真机截图暴露了第二个问题：连按三次 Shift+Tab，屏幕上留下三行

```
已进入计划模式 · 只能看不能写，用来调研并产出方案
已进入接受编辑 · 改文件不用确认，执行命令仍要确认
已进入自动模式 · 不再询问，所有工具直接执行（危险）
```

像报错刷屏。**根因不是颜色不好看，是把"状态变化"当成了"事件日志"。**

状态和日志的区别只有一条：**状态可以被覆盖，日志必须追加**。当前处在哪一档是一个状态，它应该只有一行、原地变化；"某年某月切到了某档"才是日志。之前写成了后者。

改动三处：

1. **文案压短**。`ModeSpec` 新增 `status` 字段（"只读，用来出方案"），与 `summary`（"只能看不能写，用来调研并产出方案"）分开：summary 是给没试过的人解释，可以长；status 每帧都要出现在输入行上方，必须短。
2. **覆盖而不是追加**。`LineEditor` 记住"输入行上方是否已有状态行"（`_mode_line_visible`）。已有就 `\x1b[1A\r\x1b[2K` 上移一行清掉、写新状态、`\x1b[1B\r` 回到输入行、再按可见列数右移回光标——输入行本身一个字都不用重画。首次才"擦当前行 → 写状态 → 重画输入行"。
3. **`set_mode` 不再打印任何文字**。切换只做两件事：更新状态、刷底栏（彩色那一行）。`/mode` 的输出就是那条底栏，不再补一句散文。

一个连带修正：受控帧（多行输入）下切换模式原来会响铃，现在静默返回。模式已经切好了，底栏会在这一行提交后更新；响铃只会让用户以为按键无效。

验证：`test_modes.py` 86 → **94 项**，新增"连按两次走覆盖路径""新的一行不覆盖上一行的状态行""set_mode 不再打日志""快捷键路径不刷底栏"等；全量仍绿。`--version` = 0.11.2。


## 补记（33.3）：底栏不再重复模式名

版本 0.11.2 → 0.11.3。真机截图里同一个状态出现了两次：

```
▸▸ 计划模式 · 只读，用来出方案                       ← 输入行上方：彩色、实时
> 现在进行到那里了
▸▸ 计划模式 · shift+tab 切换 · ↑↓ 历史 · ...         ← 底栏：暗灰、上一轮的旧值
```

"计划模式"说了两遍，而且下面那条还是**旧值**——底栏要等这一行提交后才重画，两条并排时互相矛盾。

三处改动：

1. **底栏去掉模式名和模式色**，整行统一暗灰，只讲"这一行能按什么"。
2. **重画逻辑回到"只画一次"**。底栏内容不再与模式有关，跟着模式重画只会每切一次多堆一条相同的底栏。
3. **`set_mode` 删掉 `announce` 参数**。它原本控制"要不要打一行 / 刷底栏"，现在两条路都不需要 `set_mode` 碰界面：`/mode` 由命令自己调 `print_mode_status` 打一行（和快捷键那条同格式、同颜色），快捷键仍交给 `LineEditor` 原地覆盖。

分工从此明确：**模式归输入行上方的状态行**（实时、有色、可覆盖），**底栏只讲操作提示**。

验证：`test_modes.py` 94 项仍全绿；底栏四档渲染完全一致（不含模式名）；`/mode plan` 输出一行 `▸▸ 计划模式 · 只读，用来出方案`。`--version` = 0.11.3。


## 补记（33.4）：子 agent 的上下文百分比要有标记

版本 0.11.3 → 0.11.4。这条与工作模式无关，是同一晚的真机反馈，一并记在这里。

截图里主对话显示 48.5%，派了 `code-reviewer` 之后紧接着一行变成 **1.0%**，看起来像主对话被清空了。

机制：`task` 派活时 `start_new_chat()` 会压一页新历史，用量账本同时压入 `TokenUsage(0,0,0)`；
`current_context_window` 读的是栈顶，也就是子 agent 自己刚起步的占用。主对话的数字没丢，
`finish_chat_get_response()` pop 之后下一行就会跳回 48.x%。

问题纯粹在显示：两个数字长得一模一样，中间没有任何标记。

改动一处：`_print_context_window_and_total_cost` 在 `is_subagent` 时把前缀换成 **"子 agent 上下文"**。
数字不变，只把"这是谁的账本"说清楚。

验证：裸对象分别以 `_task_depth=0/1` 调用，输出 `上下文 48.5%` 与 `子 agent 上下文 48.5%`；全量测试仍绿。`--version` = 0.11.4。


## 补记（33.5）：计划模式改成 Claude Code 的做法

版本 0.11.4 → 0.12.0。两条真机反馈推动了这次改动："好多 cmd 命令用不了"（`node --check`、`Get-ChildItem` 全被白名单挡）、"MCP 工具也用不了"。

三处改动：

1. **不再剪工具清单**。plan 模式下工具照常下发，写工具看得到、调用被拒。好处是方案能写具体（"用 file_edit 改 foo.ts:42"），而不是只说"改这里"；也让模型知道"这不是环境缺工具"。
2. **cmd_runner 从白名单翻成黑名单**。只拒绝明确的写操作（`rm` / `del` / `git commit` / `npm install` / `npm run build` …），其余放行。判定只看**每段的第一个词**——`cat copy.py` 不会因为文件名里有 copy 被误杀，这是整段正则匹配最容易踩的坑。解释器单独处理：`python` / `node` 只放行版本查询与 `node --check`，因为它们能执行任意代码。
3. **MCP 按 `readOnlyHint` 处理**。服务器声明只读 → 直接放行；没声明 → 问一次（回车即执行）。和 Claude Code 一致：不静默拒绝，也不静默放行。`McpTool.is_readonly` 兼容 `readOnlyHint` / `read_only_hint` / dict 三种写法，取不到一律当"能写"。

安全边界的变化要说清楚：**黑名单拦不住蓄意写入**。`python -c "open('x','w')"` 之外还有无数绕法，它的定位是"防手滑"，不是沙箱——这一点从白名单时代起就没变，只是现在把"误拦"的代价降到了最低。

验证：`test_modes.py` 94 → **110 项**，新增 13 条只读正例（含 `node --check`、`Get-ChildItem`、`git remote -v`、`tsc --noEmit`）、18 条写操作反例、以及"声明只读的 MCP 放行 / 未声明问用户"两条；全量仍绿。`--version` = 0.12.0。


## 补记（33.5.2）：MCP 的 env 支持

版本 0.12.1 → 0.12.2。给搜索 MCP 配代理时发现 `mcp.json` 里的 `env` 字段是个摆设——`client.py` 写死 `env=None`，配置里写了也传不到子进程。

三处补齐：

1. **`server_config` 读 `env`**，值统一转字符串（JSON 里写 `7890` 会被解析成整数，而环境变量必须是字符串）；整段写成非对象时只忽略该字段并提示一行，不让整个服务器连不上。
2. **`client` 合并而不是替换**：`{**os.environ, **server.env}`。stdio_client 拿到 env 是整体替换，只给代理会让子进程丢掉 `PATH` / `SystemRoot` / `APPDATA`，Windows 下最直接的表现就是"进程起不来"，而错误只说连不上。
3. **`thinker mcp add -e KEY=VALUE`**（可写多次）写进配置；输出只打 key、不打 value——代理地址和 API key 不该出现在截图和日志里。

验证：临时配置端到端跑 `add -e HTTPS_PROXY=...`，写入的是嵌套对象、读回 `env` 正确、`repr` 只显示 `env_keys`；`test_mcp_cli.py` 52 项仍绿。`--version` = 0.12.2。
