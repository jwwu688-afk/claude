## 一、病灶：为什么是"橙绿交替"

### 1.1 绿色不是我们画的

`theme.BULLET` 原来是 `⏺`（U+23FA，BLACK CIRCLE FOR RECORD）。

这个字符落在 Unicode 的「杂项符号」区，**Windows Terminal 和 conhost 会把它交给 Segoe UI Emoji 渲染**。结果是一个彩色的 emoji 圆点，而且**颜色不受 rich 控制**——写 `style="green"`、`style="white"` 都无效，终端按 emoji 字体自己的配色画。

第 7 轮把圆点写成白色、注释里写"Claude Code 里它不上色"，但在本机终端上它一直是绿油油的，这是当时没发现的。

Claude Code 自己用的是 `●`（U+25CF，BLACK CIRCLE）——纯几何字符，永远按前景色渲染。截图里 `● Skill(using-superpowers)` 和 `● 你好！` 两处绿点，都是这个字符加 `green` 样式。

### 1.2 交替的第二个成因：缓冲区的真假在抖

`_stream_renderable()` 原来这样判断：

```python
if not self._stream_buffer:
    return self._spinner_renderable()   # 橙 ✻
return self._bullet_block(...)          # 绿 ●
```

`_stream_buffer` 是"当前这一帧有没有字"。但流式接口会先发几个**空 delta**（`""`、`"\n"`），缓冲区的真假状态跟着抖，于是：

```
帧 1  空      → ✻ 橙
帧 2  "\n"    → ● 绿 + 空正文
帧 3  空      → ✻ 橙
帧 4  "你"    → ● 绿
```

每秒刷新 10 帧，屏幕上就是两个标志交替闪。

### 1.3 改法（第一版只改了一半）

第一版做了两件事：字符换成 `●`，判断换成**一次性开关**：

```python
if chunk and chunk.strip():          # 只有"有实义的字"才算开始
    if not self._stream_has_content:
        self._thought_seconds = time.time() - self._stream_start
    self._stream_has_content = True  # 置上就再也不复位

if not self._stream_has_content:     # 判断的是"这一轮有没有出现过内容"
    return self._spinner_renderable()
```

实测时序（`''/'\n'/''/'你'/''/'好'/'\n\n'`）：

```
[False, False, False, True, True, True, True]
```

**但用户反馈"还是交替闪烁"。** 说明真正的原因不在这里。

### 1.4 真正的根因：Live 重绘不清行

用 `winpty` 分配伪终端抓了一次完整输出，把转义序列拆开看：

```
等待 3 秒的 24 帧：✻(0s) ✢(0s) ✳(0s) ✶(0s) ✻(1s) … 全部是橙色 spinner ✓
清行指令 \x1b[2K 出现次数：0
```

**rich 的 `Live` 重绘方式是"光标上移 N 行，然后重写覆盖"，它从不发清行指令。**

spinner 一行大约 20 列，正文是满宽的表格（`_bullet_block` 用 `Table.grid`）。两者宽度差了一个屏幕：

```
第 N 帧    ✻ 正在思考… (2s)                        ← 20 列
第 N+1 帧  ● 你好！我是 Thinker。…（满宽表格）      ← 80 列
第 N+2 帧  ✻ 正在思考… (2s)                        ← 又回到 20 列，右边 60 列是上一帧的残影
```

橙色的 ✻ 写在行首，右边还留着绿色的 `●` 和正文——**这就是"橙绿交替闪"的真相：不是两个标志轮流画，是一个画在新的上面、另一个留在残影里。**

所以修法不是调判断，而是**让等待态根本不用 Live**：

| 阶段 | 实现 | 为什么 |
|---|---|---|
| 等待 | 后台线程 + `\r` + 重写 + 尾随空格覆盖，单行原地转 | 单行永远只有一行，旧内容被空格吃掉，不可能留残影 |
| 正文 | 第一个真字到达才创建 `Live` | 内容只增不减，高度单调变高，不存在"新帧比旧帧短" |

```python
def _spin_loop(self):
    while not self._spinner_stop.is_set():
        elapsed = time.time() - self._stream_start
        frame = theme.SPIN_FRAMES[int(elapsed * 8) % len(theme.SPIN_FRAMES)]
        line = (
            f"{theme.ACCENT_ANSI}{frame}{theme.RESET_ANSI} "
            f"{theme.DIM_ANSI}正在思考… ({int(elapsed)}s){theme.RESET_ANSI}"
        )
        sys.stdout.write("\r" + line + " " * 4)
        sys.stdout.flush()
        self._spinner_stop.wait(0.12)
```

四处细节：

1. **用 `Event.wait(0.12)` 而不是 `time.sleep`**：停止信号一到就能立刻醒，不用等这一轮 sleep 结束。
2. **`_stop_spinner()` 必须 `join`**：否则线程可能在正文开始输出之后还在往同一行写，把正文第一行覆盖掉。
3. **擦行用空格覆盖，不用 `\x1b[2K`**。2K 是标准 CSI，Windows Terminal 支持，但不是所有实现都老实执行——实测在伪终端里清行之后，上一帧的尾巴还留在右边，屏幕上是
   `✻ 正在思考… (1s)  Thought for 1s … (1s)` 这种粘连。改成 `\r` + 60 个空格 + `\r`，不依赖终端对清行指令的支持。
4. **颜色改用 256 色转义码**（`\x1b[38;5;209m`）而不是 rich 的 `rgb(...)`：rich 会生成真彩色序列 `38;2;217;119;87`，部分终端/字体组合下渲染不稳；256 色的 209 号就是 Claude 橙，兼容性更好。

另外两个伴随改动：

- **`_stop_spinner()` 只在"确实停掉了一个在跑的 spinner"时才发清行**。否则 `clear_stream_buffer()` 这类调用会顺手把用户刚敲的那一行擦掉。
- **正文 renderable 加了一级缓存**：Live 每秒取 10 次，原来每次都重新 `Markdown(...)` 解析整段；长回复时 CPU 一忙刷新就不均匀，看起来"一顿一顿"。现在只有 buffer 变了才重建。

### 1.5 第三版：还是闪，又补了三处

第二版上机之后用户反馈**仍然交替闪**。继续排查，又找到三个会制造"闪"的点：

| # | 问题 | 修法 |
|---|---|---|
| 1 | **spinner 线程会泄漏**。`stop_stream_display()` 只写在流式 for 循环后面，网络中断/解析出错会直接跳到 except，线程一直活着；下一轮再起一个，两个线程往同一行写 | ① `start_stream_display()` 开头先无条件 `_stop_spinner()`（幂等兜底）；② `conversation` 的 except 分支补 `stop_stream_display(show_done=False)` |
| 2 | **每帧宽度不固定**。秒数从 `(9s)` 变 `(10s)` 多一列，变短的那一帧右边就留残影 | 用 `rich.cells.cell_len` 把每帧 pad 到固定 28 列，再补一条 `\x1b[K`（清到行尾） |
| 3 | **短等待也画动画**。工具调用轮次常常几十毫秒就返回，spinner 刚画出来就被擦掉——这一下"画出-擦掉"本身就是一次闪 | 先 `Event.wait(0.2)`，200ms 内没等到结果就压根不显示 |

另外加了 `THINKER_NO_SPINNER=1` 开关，可以把等待动画整个关掉。不同终端的 ANSI 支持差异很大，留个一键退回的口子。

> 这一串排查里最有价值的一条：**"闪"有三种完全不同的成因**——emoji 化、残影、线程打架。现象一样，修法完全不一样。单看屏幕猜不出来，必须抓字节流。

## 二、界面还原：对着截图逐块改

### 2.1 欢迎区：去框试过，撤回了

第 7 轮是圆角框 + 居中标题。实拍截图里 Claude Code **没有框**：左边一个橙色方块 logo，右边三行左对齐文字。所以这一轮先按截图改了：

```
▄▄▄▄▄▄▄  ▄▄▄▄▄▄   Thinker v0.1.0
███████  ██████   spark-x2.6 · API Usage Billing
███████  ██████   …/code/thinker
▀▀▀▀▀▀▀  ▀▀▀▀▀▀
```

**实际跑起来很难看**：终端只能用 `█▄▀` 拼形状，`▄▄▄▄▄▄▄` 渲染出来就是一块橙色实心矩形，两个矩形并排，没有任何"图形"的感觉。

Claude Code 那个 logo 是矢量图（8-bit 风格的方块人），字符画还原不了。所以**回退到第 7 轮的圆角框版**：

```
╭──────────────────────────────────────────────────────────────────────╮
│                                                                      │
│                         ✻ Welcome to Thinker                         │
│                                                                      │
│                      spark-x2.6 · MCP 客户端版                       │
│                            …/code/thinker                            │
│                                                                      │
╰──────────────────────────────────────────────────────────────────────╯
```

教训：**截图里"看起来简单"的图形，往往恰恰是字符画最还原不了的东西**。文字排版能抄，图形不能抄——除非上图片协议（Windows Terminal 不支持）。

### 2.2 正文与工具行：绿色 ●

| 位置 | 改前 | 改后 |
|---|---|---|
| 助手回复 | `⏺ 你好`（白，实际渲染成绿） | `● 你好`（`bold green`） |
| 工具调用 | `⏺ file_read(a.py)`（同左） | `● file_read(a.py)` |
| 工具结果 | `  ⎿  …` | 不变 |

`_bullet_block` 的两列网格保留——它解决的是"折行对齐"：圆点占 2 列，正文从第 3 列开始，长段落折行时自然对齐在文字下面。

### 2.3 新增 `Thought for Ns`

截图里每次回复前面有一行 `  Thought for 4s (ctrl+o to expand)`。

含义是"模型从开始到吐出第一个字花了多久"。我们本来就在 `start_stream_display` 记了 `_stream_start`，所以只需在第一个真字到达时定格：

```python
self._thought_seconds = time.time() - self._stream_start
```

渲染时用 `Group` 把它和正文竖着拼起来，只有 `>= 1s` 才显示——否则每句快速回复上面都挂一行 `Thought for 0s`，纯噪音。

括号里的 `ctrl+o to expand` 目前没有对应功能（思考内容本来就没保存），保留它是因为这行本身就是"这是什么"的解释。

### 2.4 新增 `✻ Cooked for Ns · done HH:MM`

截图里每轮回答结束有一行收尾：

```
✻ Cooked for 7s · done 11:38
```

整行暗灰，和正文区分开。只在"这一轮模型真的说了话"时打印——纯工具调用的轮次不打，否则一屏里会出现三四条 Cooked。

### 2.5 输入框横线与底部状态栏

截图里每轮输入下面有一条贯穿窗口的细线，最底部还有一行黄字：

```
> nihao
────────────────────────────────
▸▸ auto mode on (shift+tab to cycle) · ← for agents
```

横线的实际作用不是装饰：长对话里用户输入和模型回复之间只有空行时，很难一眼找到"我上一句说的是什么"。

底部那行**保留了字形和配色，内容换成了真实存在的提示**：

```
▸▸ 默认模式 · ctrl+c 退出 · 上下文 80% 自动压缩
```

原因：`auto mode` 对应权限模式切换、`← for agents` 对应 agent 面板，这两个功能都还没有。照抄会变成"按了没反应的假按钮"，比不写更让人困惑。

状态栏只画一次（紧跟在第一次输入完成后的横线下面）。它是"底栏"，不是每轮都要重复的日志。

## 三、顺带修掉：MCP 配置指向改名前的目录

改名（`D:\code\claude` → `D:\code\thinker`）之后，三处 `mcp.json` 里的绝对路径还是旧的：

| 文件 | 影响 |
|---|---|
| `src/mcp_servers/mcp.json` | 仓库内的示例配置 |
| `~/.thinker/mcp.json` | 程序优先读的那份 |
| `~/.quickstar/mcp.json` | 回退用的那份 |

```
can't open file 'D:\code\claude\src\mcp_servers\weather.py'

```

三处已一并改成 `D:\code\thinker\...`，重启后连接恢复正常。

