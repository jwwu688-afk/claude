# 第 22 轮：会话内换模型（`/model`）

> 日期：2026-11-11
> 版本：0.10.1（新增命令，发布时建议递增到 0.11.0）
> 触发：用户提出「想加一个 `/model` 斜杠命令，可以选模型」
> 教训：**凡是"改一个值"的需求，真正的成本都在那几个跟着一起变的地方**

---

## 一、现象

换模型只能改 `.env` 里的 `OPENAI_MODEL` 再重启。而人换模型的时机几乎都在对话中间：

- 「这句话很简单，不值得用贵的模型」；
- 「这个模型答得不好，换一个试试」。

为了改一行字丢掉正在进行的对话，很不划算。另一个问题更隐蔽：**用户不知道该填什么名字**。
中转站的模型清单动辄上百条，靠记忆写模型名，写错的代价是一次 400。

## 二、做法：只有一条命令，没有参数

```
/model     读出清单 → 编号选择 → 切换
```

第一版还带过 `/model <名字>`（直接切）和 `/model list [关键词]`（只看清单），
按需求砍掉了。砍掉的理由不只是"少一个语法分支"：

**"直接打名字"这条路有个绕不开的两难。**
要么联网校验名字是否存在——把最该快的那条路径变慢，而且很多中转站的清单并不全
（返回 200 但只列了几十个），严格校验会把明明能用的模型挡在门外；
要么不校验——名字打错就切到一个不存在的模型，下一条消息直接 400，
而那条报错信息跟"换模型"这件事看起来毫无关系，用户会以为是切换把对话弄坏了。

两个选项都不好，那就不提供这条路：**能选的名字一定来自清单，必然是真实存在的**。

### 清单从哪来

```text
GET /v1/models ──成功──→ 去重排序 → 候选
      │
      └─失败/空────────→ OPENAI_MODELS（.env 逗号分隔）──→ 候选
                              │
                              └─也没有──→ 报错，并指向 OPENAI_MODELS
```

`/v1/models` 不是 OpenAI 兼容接口的强制项，很多中转站根本没有这个路由。
所以失败不能报错收场，必须让"手写清单"的人还能用——这也让 `.env` 里的
`OPENAI_MODELS` 从"可有可无的兜底"变成了这条命令的**必备配置项**，
`.env.example` 里的注释已按这个定位改写。

**超时要显式压到 10 秒**：SDK 默认是 10 分钟。用户只是敲了个 `/model`，
界面卡十分钟，他只会以为程序死了。用 `client.with_options(timeout=10)` 临时覆盖，
不动全局 client——改全局会影响真正的对话请求。

### 清单不截断，全部列出来

本来可以只显示前 12 条防刷屏，但那会让**排在第 13 位之后的模型永远切不到**：
用户看不到就不敢输编号，输了越界也只会被当成取消。
而"能切到想要的模型"是这条命令唯一的功能，功能完整优先于观感。
代价是模型特别多时要滚一屏——一次性输出，滚过去就没了，比"永远选不了"划算。

排序上仍然偏心：当前模型永远第一（最常见动机是"确认我在用哪个"），
其余按"像不像对话模型"分组（gpt / claude / deepseek … 在前，
embedding / tts / dall-e 在后）。关键词只用于排序，**不做过滤**——
误判只是位置差一点，不影响正确性。

## 三、真正麻烦的地方：切模型不只是改一个字段

这是本轮唯一需要动脑的地方。`self.model = name` 之后，有三个连带状态会变成不一致：

| 连带状态 | 不处理的后果 |
|---|---|
| `summary_model` | 主模型换了、压缩还在用旧的。旧模型可能已经下线 |
| `prompt_cache_enabled` | 从 claude 切到 gpt 后仍打 `cache_control` 标记 → OpenAI 官方接口直接 **400** |
| 回执里的旧模型名 | 用户看不到自己从哪切过来的 |

前两条必须在 `APIClient.switch_model()` 里一起做，命令层只负责打印。
把它们写在命令层，等于让界面代码去维护请求层的正确性——迟早漏一个调用方。

### 摘要模型：只有"继承型"才跟着换

`.env` 里 `OPENAI_SUMMARY_MODEL` 有两种语义：

- **留空** → `summary_model = 主模型`，本质是"跟着走"。主模型换了，它就该跟着换。
- **显式配置** → 用户特意配个便宜小模型省钱。切主模型**不能**动它，
  否则用户配的省钱方案会被悄悄改掉，而且他完全不知道。

这两种在合并成 `self.summary_model` 之后就分不出来了，所以在 `__init__` 里
多存一个 `_summary_inherits`（依据是"启动时那个环境变量是不是空的"）。
一个布尔值换掉一类难查的静默行为改变，值得。

### 缓存标记：按新模型重算，但用户配置优先

`_detect_prompt_cache()` 原本就支持三级判断（环境变量 > 地址含 anthropic > 模型名含 claude），
切完模型重算一遍即可。

实测发现一个真实情况：开发机 `.env` 里写着 `ENABLE_PROMPT_CACHE=0`。
此时无论怎么切模型，缓存标记都必须保持关闭，并且**不提示"已变化"**——
用户显式配置的优先级高于自动推断，这条在改前就是对的，切换时不能破坏它。

## 五、验证（不联网、不调模型）

用 Fake API / Fake UI 跑通这些路径：正常选择、取消（回车）、带多余参数的提示
（`/model gpt-4o` 会提示"不带参数"但不中断，照样列出清单）、接口失败退回 env、
清单全空、子 agent 拒绝。另外单独验证：

- 排序：当前模型第一且不重复；gpt/claude 排在 embedding/tts 之前；
- `switch_model`：首尾空格被 strip；继承型摘要跟着换；显式摘要不动；
  `ENABLE_PROMPT_CACHE=0` 时切模型不改标记；未配置时 claude → 开、gpt → 关；
- 空名字抛 `ValueError`；
- `/help` 排版：新行摘要不折行、不错位。

真实接口的清单没有跑（`/v1/models` 不属于对话请求，但按约定不自行触发），
由用户首次使用时确认。

## 六、遗留

- **清单拉不到时无能为力**：只能去 `.env` 配 `OPENAI_MODELS`。这是砍掉"直接打名字"
  之后的必然代价，已写进命令的报错提示和 `.env.example`。
- **会话文件头的 `model` 字段不更新**：header 是"开这个会话时用的模型"的快照，
  中途切换不会改写第一行（重写文件头风险大于收益）。看 `--continue` 的列表时，
  显示的是启动时的模型。
- **上下文窗口仍按 `.env` 的 `MODEL_MAX_TOKENS` 估算**：换到窗口差很多的模型时，
  占用百分比会失真。回执里已提示"窗口不同请自行调整"，自动识别需要一个
  模型→窗口的映射表，而中转站的模型名根本对不上官方表，做了也不准。
