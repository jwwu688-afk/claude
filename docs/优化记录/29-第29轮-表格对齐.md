# 第 29 轮：流式正文里的 markdown 表格，按显示列对齐

日期：2026-11-11
版本：0.10.2（未发版）

## 现象

用户截图：模型输出的连击系统改动说明是一张表，但屏幕上是原始 markdown：

```
| 改动文件 | 内容 |
| --- | --- |
| `game.js` | `combo`/`comboTimer` 字段、`comboMul` 倍率计算、击杀累加连击并应用倍率分数、受伤/超时清零 |
```

竖线位置参差不齐，"对不齐"。

## 为什么没对齐

两件事叠在一起：

1. **plain 模式不做 markdown 渲染**（第 11 轮的取舍）。为了在 conhost 上不出现重影，
   流式正文是"追加式纯文本输出"，`| a | b |` 会原样打在屏幕上，rich 的表格渲染根本没用上。
2. **模型写的列宽是随手定的，而中文占两列**。`| --- | --- |` 这一行只有 7 个字符宽，
   下面的内容行光中文就有十几列——就算把 `-` 补长，也得知道"这一列最宽的格子有多宽"。

结论：要对齐，必须在**整张表收完之后**重排一次。逐行边收边打永远做不到。

## 改法

`print_streaming_content` 的 plain 分支改走 `_write_plain(chunk)`，一个很轻的状态机：

| 当前状态 | 收到 | 动作 |
|---|---|---|
| 行首、下一个字符是 `\|` | 表格行 | 进入攒表模式，**不输出** |
| 攒表中 | 又一行 `\|...` | 继续攒 |
| 攒表中 | 第一行非 `\|` | 先把整张表对齐输出，再输出这一行 |
| 非表格 | 普通文本 | 立刻写出去，**逐字手感不变** |

关键点：

- **只认行首的 `|`**。行中间的 `a|b` 是正常文本，绝不能被误当成表格
  （`_is_table_row` 要求 `strip()` 后以 `|` 开头）。
- **按显示列补齐**，不是按字符数：`_render_markdown_table` 用 `cell_len` 算每列最宽，
  `cell + " " * (width - cell_len(cell))`。中文一格算两列，补完才是真的对齐。
- **分隔行单独处理**：`| --- | --- |` 不参与宽度计算（否则一串短横线会把列撑得没意义），
  渲染时统一输出 `width` 个 `-`。
- **收尾必须 flush**：模型很可能"写完表格就结束"，没有下一行来触发"表格结束"。
  `stop_stream_display` 里先 `_flush_plain()`，否则最后一张表永远出不来。
- **40 行上限**：超过就先输出、退出攒表模式。一张巨表如果等到全部写完才显示，
  界面上看起来就是卡住了。

## 效果

`Console(width=120)` 抓纯文本，同一段内容：

改前（原始 markdown，列边界天南地北）：

```
| 改动文件 | 内容 |
| --- | --- |
| `game.js` | `combo`/`comboTimer` 字段、… |
```

改后（每行都是 108 列，竖线严格对齐）：

```
| 改动文件     | 内容                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------- |
| `game.js`    | `combo`/`comboTimer` 字段、`comboMul` 倍率计算、击杀累加连击并应用倍率分数、受伤/超时清零 |
| `effects.js` | `combo` 音效（上扬 sine）、跨档震屏、Canvas 右上角绘制倍率+倒计时条                       |
| `README.md`  | 规则说明补充连击系统                                                                      |
```

## 验证

不联网、不调模型，三种喂法都跑过：

```
整块喂入   → 5 行全部 108 列，竖线对齐
逐字符喂入 → 同上（状态机能处理被切碎的 chunk）
表格即结尾 → 收尾 flush 生效，表格完整出现
行内竖线   → "结果是 a|b 这种写法" 原样输出，没被误判
```

## 剩下的

- 表格会出现"延迟"：从第一行到表格结束之间屏幕上空白，通常一两秒。这是对齐的代价
  （不知道所有行就不可能算列宽）。如果用户觉得等得太明显，可以改成"先歪着输出，
  收尾时不再重排"——那就退回现在的样子了，不值得。
- 表格里的 `**加粗**`、`` `代码` `` 记号仍然原样显示（plain 模式本来就不渲染 markdown）。
  用户这次只提对齐，没提记号。
