## 一、怎么确认"Claude Code 到底长什么样"

不靠印象，直接看本机装的版本：`claude --version` → **2.1.317**。

它是个编译过的 338MB 单文件二进制，但里面能提取到原始字符串。从里面挖到三条关键信息：

| 挖到的内容 | 说明 |
|---|---|
| `r(n,{color:"claude",children:["Welcome to Claude Code"," "]})` | 标题用的是名为 `claude` 的颜色（即品牌橙 #D97757），不是随便一个色 |
| 存在 ` esc to interrupt` 字符串 | 等待时有 spinner，且带这个后缀 |
| 没有 `██` 之类的大号方块字符 | 新版欢迎页**不是** ASCII 大字标题，而是普通字号的标题 + 边框 |

这三条直接决定了改法方向：**上色要克制、等待要有动画、欢迎页用框而不是大字**。

## 二、改了什么

### 2.1 配色：从彩虹渐变改成 Claude 橙 + 黑白灰

```text
# 第 5 轮
ACCENT = "cyan"           # 青色
+ HSV 渐变（青→蓝→紫→洋红→红橙）+ 渐变分隔线 + 星形装饰带

# 第 7 轮
ACCENT = "rgb(217,119,87)"  # Claude 品牌橙 #D97757
```

Claude Code 的界面其实非常克制：**绝大多数文字是默认白/灰**，只有三处上色——品牌橙（✻ 和提示符）、绿（成功/新增）、红（失败/删除）。

所以这一轮删掉了：渐变函数、扫光动画、星形装饰带、渐变大字标题。净减 93 行。

### 2.2 欢迎页：方框 + 居中标题

**改前**（第 5 轮的彩色大字，5 行高、带扫光）：

```
                    ✦ · ✧ · ✦ · ✧ · ✦ · ✧ ·
             ███  █   █ ███  ████ █   █  ...
            █   █ █   █  █  █     █  █  ...
            ████  ███  ███  ████ █   █  ...
  ✦ ──────────────────────────────────────── ✦
   模型  spark-x2.6        目录  …/code/thinker
```

**改后**：

```
╭──────────────────────────────────────────────────────────────────────╮
│                                                                      │
│                        ✻ Welcome to Thinker                        │
│                                                                      │
│                      spark-x2.6 · MCP 客户端版                       │
│                            …/code/thinker                             │
│                                                                      │
╰──────────────────────────────────────────────────────────────────────╯
  输入问题开始 · Ctrl+C 退出 · 上下文 80% 自动压缩
```

三个细节：

- **圆角边框**用 `box.ROUNDED`，边框颜色是暗灰（不抢内容）
- **整体居中**，靠 `Text(justify="center")` 实现
- **`safe_box=False`**：rich 默认在"看起来不像真终端"时会把圆角 `╭` 换成方角 `┌`，导致同一个程序在终端里和重定向到文件时长得不一样。这里关掉，统一圆角

### 2.3 输入提示符：`❯` → `>`

```text
# 改前
PROMPT = "❯"  # 青色
return f"\x1b[36m{PROMPT}\x1b[0m "

# 改后
PROMPT = ">"  # Claude Code 用的是 >
return f"\x1b[38;5;209m{PROMPT}\x1b[0m "
```

颜色用 256 色里的 209 号（最接近 Claude 橙），比真彩色码兼容性更好，老终端也认。

### 2.4 正文排版：⏺ 与首行同排

这是最容易忽略、但观感差别最大的一处。

**改前**：圆点单独占一行，正文从下一行开始缩进

```
⏺
  目录里有 a、b、c 三个文件，另外还有……
```

**改后**：圆点和第一行文字同一行，续行对齐在文字下面

```
⏺ 目录里有 a、b、c 三个文件，另外还有
  .idea、docs、src、test 四个子目录。
```

实现方式（`_bullet_block`）：

```text
grid = Table.grid(padding=(0, 0))
grid.add_column(width=2)   # 第一列：圆点占 2 列（符号 + 1 空格）
grid.add_column()          # 第二列：正文
grid.add_row(Text("⏺"), Markdown(content))
```

用两列网格让表头对齐，正文折行时自然落在第二列起始位置。

> **踩坑记录**：先用 `width=1 + padding=(0,1)`，结果变成 `⏺  目录`（两个空格），续行缩进 3 格。反复试了三组参数才对齐：`⏺` 在 rich 里按 1 列宽计算，但视觉上需要 2 列——所以必须 `width=2` 且 `padding=0`。

### 2.5 等待动画：✻ 旋转 + 秒数

以前按回车后到模型开口之间，屏幕上什么都没有（1-3 秒的空白）。

现在复用流式显示那块区域：**缓冲区为空时显示 spinner，一收到第一个字就自动切回正文**。不需要额外的 Live 对象，也不会和正文打架。

```
✻ 正在思考… (3s)
```

星号在 `✻ ✢ ✳ ✶` 之间每秒切 8 次，秒数由"当前时间 - 开始时间"实时算出来。

一个坑：纯工具调用的轮次（模型不说话、直接调工具）结束时，spinner 会残留在屏幕上，和后面的 `⏺ cmd_runner(dir)` 粘在一行。解决办法是把这块 Live 标记成 `transient = True`——rich 停止时会自动擦掉，而不是把最后一帧留下。

### 2.6 符号颜色归位

| 符号 | 改前 | 改后 |
|---|---|---|
| `⏺` | 青色 | 白色（Claude Code 里它不上色） |
| `⎿` | 青色加粗 | 暗灰 |
| `✻`（spinner） | — | Claude 橙 |

## 四、和 Claude Code 仍然不一样的地方

诚实说明，这些是"知道但没做/做不到"的：

| 差异 | 原因 |
|---|---|
| 没有 `/help`、`/status`、`/compact` 这些斜杠命令 | 我们还没实现命令系统，在欢迎页写出来就是骗人 |
| 工具名是 `cmd_runner` 而不是 `Bash`/`Read`/`Edit` | 工具架构不同，改名会牵连一堆东西 |
| 没有 diff 着色（`+` 绿 / `-` 红） | 我们没有"改文件"工具，全是 shell 命令，产出的是纯文本 |
| spinner 没有 `(esc to interrupt)` | 我们确实不支持中断，写上去等于虚假提示 |
| 欢迎框的文字内容不完全一样 | 只从二进制里提取到片段，没有拿到完整模板，属于"按结构复刻" |
| 没有 `↓ 1.2k tokens` 的实时计数 | 流式过程中拿不到累计 token，只能结束后显示 |
