# 第 16.2 轮：输入层重做（整行自管）

> 日期：2026-11-08
> 版本：0.7.1 → 0.7.2
> 触发：用户实测 16.1 之后说「还是一样的问题，没有解决」
> 教训：**吞异常 + 静默降级，会让一个"修好了"的补丁看起来毫无作用**

---

## 一、16.1 的修法本身是坏的

16.1 的思路是：先探一个字符判断是不是 `/`，不是就**塞回控制台缓冲区**，再交给 `input()`。

```text
if not self._editor.unget(first):
    return input(prompt + first)     # 塞不回去就退回老办法
return input(prompt)
```

`unget` 的实现是 `self._msvcrt.ungetch(char)`，外面包了一层 `try/except: return False`。

实测这一行**每次都失败**：

```text
ungetch('a')  -> TypeError: ungetch() argument must be a byte string of length 1, not str
ungetch('帮') -> TypeError（同上）
ungetwch('a') -> 成功
ungetwch('帮') -> OSError: [Errno 0] Error
```

两个问题叠在一起：

1. **`ungetch` 要的是 bytes（`b"a"`），我传的是 str** —— 参数类型就是错的，无一次例外；
2. 就算换成宽字符版 `ungetwch`，**中文也会抛 OSError**。

而 `except Exception: return False` 把这个失败**完全吞掉**了，代码静默退回
`input(prompt + first)`——也就是 16 轮那个有 bug 的老写法。

所以用户看到的症状和没修一模一样：第一个字删不掉、提示符可能被盖掉。
从用户角度就是"你说修好了，其实一点没变"。

**这是本轮最该记住的东西**：一个降级分支如果永远不会成功，
它就不是"兜底",而是"把 bug 藏起来"。至少应该往 stderr 打一行。

---

## 二、改法：不再往 input() 交还字符

既然"塞回去"这条路走不通，就不要了。

```text
_read_line():
    completer 为 None / 逃生开关打开 / 环境不支持  →  input(prompt)      # 老路
    其余                                          →  LineEditor.readline(prompt, completer)   # 全程自管
```

**只要需要补全，整行都由 `LineEditor` 自己读**。没有"交给 input() 一部分"这回事，
也就没有"字符要不要还回去"的问题。

顺带解决了提示符的问题：`>` 由 `LineEditor` 自己写，屏幕上所有字符出自同一处，
rich 和 `input()` 抢输出顺序、把提示符盖掉的情况不会再发生。

---

## 三、连带修掉：中文退格会花屏

自管模式下退格是手动写的 `"\b \b"`，它只退**一列**。而中文占**两列**，
所以删一个中文字会留下半个字的残影——用户主要输入中文，一退格就花。

修法是按显示宽度算：

```text
width = display_width(text)          # 中文 2 列、ASCII 1 列
self._write("\b \b" * width)
```

`display_width` 用 `unicodedata.east_asian_width`，W（Wide）和 F（Fullwidth）算两列。
Ambiguous（A）按一列算——宁可少擦一格让人看到残留，也不要多擦把提示符擦掉。

同一个函数也让 `_redraw`（补全时的重画）不再需要"含中文就换行"那条特殊路径，
现在统一原地替换，屏幕上不会再留一串中间状态。

## 四、这次终于能测到按键层了

16 / 16.1 两次翻车的**共同原因**：`readline` 依赖真键盘，测不了。

所以给 `LineEditor` 加了一个按键注入口：

```text
editor = LineEditor(key_reader=iter(["帮", "\x08", "好", "\r"]).__next__)
```

测试里继承一下、把 `_write` 换成记录器，就能把整条按键路径跑一遍：

| 用例 | 断言 |
|---|---|
| 中文输入 | `["帮","我","看","看","\r"]` → `"帮我看看"` |
| **删到空再输入** | `["帮","\x08","\x08","好","\r"]` → `"好"`（16 轮那个 bug 的正面回归） |
| 删中文按两列擦 | 屏幕上出现 **2** 组 `"\b \b"` |
| 删 ASCII 按一列擦 | 出现 **1** 组 |
| Esc 清空 | `["你","好","\x1b","行","\r"]` → `"行"` |
| 方向键 | `["a","\x00","H","b","\r"]` → `"ab"`（键码不进入内容） |
| Ctrl+C | 抛 `KeyboardInterrupt` |
| Tab 端到端 | `["/","c","o","s","\t","\r"]` → `"/cost "` |

这些断言写的是**用户能观察到的结果**（返回什么、屏幕上写了什么），
不是"我的实现长什么样"——16 轮那条 `seen_prompts == ["> 帮"]` 就是反面教材。

## 五、逃生开关

```text
THINKER_PLAIN_INPUT=1     # 强制回到原生 input()，代价是没有 Tab 补全
```

留这个口子是因为：**自管模式下的中文输入法行为，我在测试环境里验证不了**
（`isatty()` 在管道里永远是 False）。万一某个终端或输入法下中文打不出来，
用户可以立刻回退，而不是只能等我改。

## 六、已知限制（自管带来的能力退步）

| 能力 | 状态 |
|---|---|
| 行内左右移动光标 | **没有**。Home/End/方向键被忽略 |
| 上下键翻历史输入 | **没有** |
| 删中间的字 | **没有**，只能从末尾退格 |
| 粘贴多行 | 换行会被当成"提交"，变成多行输入 |
| 非 BMP 字符（部分 emoji） | 会拆成代理对，可能异常 |

这些是"自己实现行编辑"的代价。要不要补，取决于实际用起来有多别扭——
如果最常用的是"打错了退格重打"，现状够用；如果经常要改句子中间，就得做光标。
**先让用户用几天再说，别提前设计。**

## 八、这一轮的三条教训

1. **不许 `except Exception: return False` 这种静默降级**。要么让异常冒出去，
   要么至少往 stderr 打一行。16.1 的问题不是"写错了 API"，而是"错了还装作没事"。
2. **测试没覆盖到的路径，等于没修**。16 轮和 16.1 都在 `readline` 上翻车，
   因为它测不到；加了按键注入口之后，那一片区域才第一次被看见。
3. **不确定的 API 先跑一行代码验证**。`ungetch(str)` 是不是 Typeerror，
   一行 `python -c` 就能知道——我却先写了整套逻辑和文档。
