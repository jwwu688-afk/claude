## 一、为什么做这件事

原来的提示词是照 Claude Code 抄的英文版。英文提示词本身没问题，但对这个项目来说有三个实际影响：

1. 你在 UI 上、在日志里、在工具返回里看到的是中英混杂，排查问题时要在两种语言间来回切
2. 想改提示词（比如调整"什么时候该用 todo"）时，得先读懂英文长句
3. 工具返回给模型的错误信息是英文（`Cannot crop: insufficient messages`），模型回复你时也会跟着掺英文

这一轮把这些全部统一成中文。

## 三、故意保留英文的部分

| 保留项 | 例子 | 原因 |
|---|---|---|
| 工具名 | `cmd_runner`、`todo_write` | 是程序内部标识符，改名会牵连 `ToolManager` 注册和 MCP 配置 |
| 参数名 | `command`、`timeout`、`todos`、`crop_direction` | 同上，是 JSON 契约 |
| 枚举值 | `pending`、`in_progress`、`completed`、`top`、`bottom` | 代码里有字符串比较，改了逻辑就断 |
| JSON 字段 | `type`、`text`、`role` | OpenAI 接口协议要求 |
| 命令 / 路径 / 代码标识符 | `git status`、`cat -n`、`src/foo.c`、`isPrime` | 翻译了就不能用了 |
| 系统自动生成的元数据 | schema 里的 `title: State` | FastMCP / Pydantic 自动生成，改不了 |

## 五、过程中的两个发现

### 5.1 FastMCP 不解析参数说明（不是本轮引入的）

改 MCP 服务器文档字符串时，发现参数说明是空的：

```
[state]            ← 空
[number1]          ← 空
```

查了原始 schema 才确认：这个版本的 FastMCP 只把 `title`/`type` 放进参数定义，不解析 docstring 里的参数说明。

```json
{"properties": {"state": {"title": "State", "type": "string"}}, "required": ["state"]}
```

也就是说**改之前也是空的**，不是本轮造成的。不过为了兼容将来支持解析的版本，我把文档字符串的格式从「参数：」改回了 `Args:`（内容仍是中文），这是 docstring_parser 认的关键字。

### 5.2 中文提示词的效果需要用真实请求验证

本轮**没有发起任何真实 API 调用**（要花钱），所以"翻译后的提示词能不能让模型同样守规矩"这件事没有实测。

理论上中文提示词对 Claude / GPT 都工作良好，但有两处值得你亲自跑一次确认：

1. 「简洁，少于 4 行」这类约束，中文表达是否同样有效
2. 「不要添加任何注释」这条，中文是否同样被遵守

如果你跑一轮觉得模型变啰嗦了，把 `system_rule.py` 里「语气与风格」那一段调回去或收紧即可，不涉及其他代码。
