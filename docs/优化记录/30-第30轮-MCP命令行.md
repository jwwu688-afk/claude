# 第 30 轮：MCP 命令行（`thinker mcp add/remove/list/get`）

> 日期：2026-11-12
> 版本：0.10.2（本轮未动版本号；第 26 轮起就没有再逐轮进位，要发版时统一升到 0.11.0）
> 触发：想给 Thinker 加 MCP 服务器，得手动编辑 `~/.thinker/mcp.json`；照着 Claude Code 的 `claude mcp add` 做成命令
> 教训：**凡是「整份读进来、改一项、整份写回去」的操作，写之前必须先确定自己读懂了这份文件——读不懂就停手，别拿「当作空配置」兜底**

---

## 一、一句话方案

把「接一个 MCP 服务器」压成三个信息：名字、启动命令、命令参数。剩下的事（JSON 格式、转义、覆盖前备份、坏文件保护）由命令负责。

```bash
thinker mcp add 12306 -- npx -y 12306-mcp
thinker mcp remove 12306
thinker mcp list
thinker mcp get 12306
```

只做 stdio，其他类型明确报错——因为客户端根本没有 http/sse 的通道（`server_config.py` 会跳过它们），放行等于让用户以为配上了。

---

## 二、改前 vs 改后

**改前**：接一个服务器要开 `~/.thinker/mcp.json`，自己补 `{ }` `[ ]`，记清 `type/command/args` 三个键。写错一个逗号，运行时只打一行「配置文件解析失败」然后跳过全部外部工具——用户看到的是「工具凭空消失」。

**改后**：

| 动作 | 改前 | 改后 |
|---|---|---|
| 添加 | 手写 5 行 JSON | `thinker mcp add 12306 -- npx -y 12306-mcp` |
| 删除 | 手找那一段，还得处理尾逗号 | `thinker mcp remove 12306` |
| 确认当前有哪些 | 打开文件读 | `thinker mcp list` |
| 写错格式的代价 | 全部外部工具静默失效 | 命令当场报错，文件一个字节没变 |

---

## 三、命令契约

| 命令 | 行为 | 失败时 |
|---|---|---|
| `add <名字> -- <命令> [参数...]` | 写入/覆盖；同名覆盖并备份 | 名字非法、缺命令、类型非 stdio、文件坏 → 返回码 1，磁盘不动 |
| `remove <名字>`（`rm`） | 删除并回显被删的命令 | 名字不存在 → 列出已有名字后返回 1 |
| `list`（`ls`） | 表格：名字 / 类型 / 完整命令 | 非 stdio 的条目标「忽略」 |
| `get <名字>` | 输出该条 JSON 原文（不重排、不隐藏未知字段） | 不存在 → 返回 1 |

解析规则（`--` 是核心）：

- `--` 之后全部原样交给子进程，所以 `npx -y` 里的 `-y` 不会被当成 Thinker 的选项吞掉。
- `-t/--transport` 写在名字前后都认（对齐 `claude mcp add name -e K=V -- cmd` 的顺序），只要在 `--` 之前。
- 省掉 `--` 也能用（`add 12306 npx -y 12306-mcp`）：名字之后遇到第一个非选项 token，就认为命令开始了。

---

## 四、怎么保证不写坏用户配置（本轮真正的重点）

三条硬规矩，都写在 `tools/mcp_config.py` 里：

1. **严格读**：JSON 不合法、最外层不是对象、`mcpServers` 不是对象 → 抛 `MCPConfigError`，命令中止。绝不「当作空配置」继续，否则写回时会把用户手写的服务器全删掉。错误信息带行号列号（`json.JSONDecodeError` 本来就有，别浪费）。
2. **写前备份**：目标文件已存在时先 `copy2` 成 `mcp.json.bak`。备份失败就中止——没有退路就不覆盖。
3. **原子替换**：先写同目录 `.tmp`，再 `os.replace`。写到一半断电/被杀进程时，原文件还是完整的那一份。

另外两件小事：读文件用 `utf-8-sig`（记事本存过带 BOM 的文件，普通 utf-8 读出来首字符是 `\ufeff`，`json.loads` 直接失败）；写回时 `ensure_ascii=False`，中文和 emoji 原样留着。

4. **沿用原文件缩进**：`json.dumps(indent=...)` 的缩进从原文件嗅探（tab / N 空格）。这条是拿真实配置试出来的——用户手上那份是 tab 缩进，统一成 2 空格会让「加一个服务器」的 diff 变成整份文件重写。实测：在一份 tab 缩进的配置上加一条，`diff` 只有新增的 8 行（外加补了文件末尾换行）。

运行时那条路保持不变：`MCPConfig` 仍然是「坏一条跳一条，程序必须能起来」。两条路分工写进了两个文件的头部注释——**容错加载**（运行时）和**严格加载**（编辑时）目标不同，不能合并。

## 五、路径只有一个真源

`~/.thinker/mcp.json` 的定位原来只写在 `MCPClient._resolve_config_path()` 里。命令也要写同一个文件，两份路径逻辑迟早走岔（「命令写进 A、程序读 B」）。所以搬到 `tools/mcp_config.resolve_config_path()`：

优先级 环境变量 `THINKER_MCP_CONFIG` → `~/.thinker/mcp.json` → `~/.quickstar/mcp.json`（老路径兜底，仅当新路径不存在）。

环境变量这一条是给测试用的：测试必须能把配置指到临时目录，否则跑一次测试就等于动一次用户真实配置。

`tools/mcp_cli.py` 特意**不放进** `tools/mcp_client/` 包：那个包的 `__init__.py` 会 import client → import `mcp`、`anthropic`。改几行 JSON 没必要拉起整套重依赖（实测 `import tools.mcp_cli` 后 `mcp` 不在 `sys.modules` 里）。

## 六、验证

`python test/test_mcp_cli.py` —— 47 条断言，不联网、不消耗模型额度、不碰真实配置。重点覆盖：

- 命令写出来的文件，运行时 `MCPConfig` 必须读得懂（用临时文件对读了一遍，`MCPServer` 构造参数完全一致）；
- 覆盖同名服务器时，备份里必须是**旧**内容；
- 配置文件是坏 JSON 时，`add` 和 `remove` 都中止且原文件字节不变；
- 各种用法错误（缺命令、名字含斜杠/空格、`--transport http`、未知选项）一律返回 1 且不动磁盘；
- 文件里的 `_说明` 之类手写键、其他服务器，不能因为一次 add 就消失。

回归：`test/test_compress_boundary.py` 仍是 37/37。

## 七、没做的事（以及为什么）

- **不支持 `-e KEY=VALUE` 环境变量**：`MCPServer` 和 `stdio_client` 现在都是 `env=None`（继承父进程），命令里放行 `-e` 只能做到「写进 JSON」，运行时并不生效——那是最坏的一种成功。要加得先改客户端传 `StdioServerParameters.env`。
- **不支持 http/sse**：客户端没这条通道，见上。
- **不支持 `--scope project`（项目级配置）**：目前只有全局一份 `~/.thinker/mcp.json`。项目级配置要连带解决「哪个目录算项目根」「多份配置怎么合并重名」两个问题，不塞进这一轮。
  （第 30.2 轮补）现在按 claude 习惯写 `-s user` / `--scope=project` 会直接报错并给出正确写法。原来它落到通用的「不认识的选项……命令自己的参数请写在 `--` 后面」，那句提示会把人带偏：`-s` 确实是配置选项，只是我们没有这一维，而不是参数写错了位置。
- **不做热加载**：命令只改文件，改完退出，下次启动生效。往一个已经握有 MCP 会话的工具表里临时插条目，容易把工具表搞脏，收益不值这个风险。
