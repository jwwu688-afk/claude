# 第 18.7 轮：Esc 在模型思考时也能打断

> 日期：2026-11-09
> 版本：0.9.2 → 0.9.3
> 触发：用户实测「模型思考的时候按 Esc 并没有用」
> 教训：**检查点写在循环体里，就等于「循环开始之前」永远没有检查点**

---

## 一、现象

问一个要思考 11 秒的问题（运行结束会显示 `Thought for 11s`），这 11 秒里按 Esc
完全没反应。等模型开始吐字了再按，就能打断。

## 二、根因

本项目的 Esc 检查点是这么写的：

```python
for chunk in iterator:          # ← 阻塞在 next() 上等网络
    if esc.triggered: break     # ← 只有"收到一块数据"才会执行到
```

模型思考时，`iterator` 里一个元素都没有，`for` 的循环体**一次都不执行**。
EscWatcher 在后台线程里每 50ms 把标志位置真了，但主线程根本没机会看它。

标志位是对的、线程是活的，**只是检查点放错了地方**。这类 bug 看代码很难发现：
`if esc.triggered: break` 明明写在那里，但它执行不到。

## 三、修法：读流放到后台线程

```text
主线程                          后台泵线程
  ├─ 每 50ms 看一眼 Esc           ├─ for item in iterator
  │    按了 → 抛 StreamInterrupted │     ├─ 有数据 → 塞进队列
  └─ 队列取到数据 → 照常处理       └─ 读完 → 塞"结束"标记
```

新增 `src/core/stream_pump.py`：

```python
for chunk in iter_stream_with_esc(iterator, esc):
    ...
```

- `esc` 为 `None`（非 Windows / 非终端 / 管道）时直接透传，行为和改前完全一致；
- 源流的异常原样抛到主线程，调用方原有的非流式 fallback 不受影响；
- 收到"完整消息"后调用方 `break` → 生成器关闭 → `finally` 通知泵线程收工。

**为什么不用 asyncio 的 `wait_for` 超时**：这里的流是 openai SDK 的**同步生成器**，
没有 await 点，`wait_for` 管不到它。除非把整个客户端换成 `AsyncOpenAI`——
那是另一个量级的改动，不值得为"按 Esc 要等 11 秒"换掉客户端。

## 四、已知的边角

| 边角 | 说明 |
|---|---|
| 打断后泵线程可能多消费 1 块 | 它可能正好卡在 `next(iterator)` 上，那块数据到达后才看到 stop 标志。daemon 线程，不影响主流程 |
| 打断时可能已经产生费用 | 请求已经发出去了，Esc 只是不再等它，token 照算。这是所有 CLI agent 的共同点 |
| 首字节到达前打断 | 保存下来的内容是空的，界面提示"已中断（Esc）"，不进历史——这是对的，半句话都没说 |
