## 一、终于把两套记忆分清了

第 11 轮做完 `THINKER.md` 之后，很多人（包括我）会以为"记忆功能做完了"。其实 Claude Code 有**两套**：

| | THINKER.md | MEMORY.md |
|---|---|---|
| 谁写 | 人 | **模型自己** |
| 存哪 | 仓库里，跟着 git 走 | `~/.thinker/projects/<项目>/memory/`，不进仓库 |
| 内容 | 项目规矩（怎么跑测试、不要动哪个文件） | 经验（用户纠正过什么、踩过什么坑） |
| 注入 | 全文 | **只有索引**，细节按需读 |

为什么必须分开：

- **项目规矩是"共识"**：应该进仓库、团队共享、稳定不变。
- **经验是"个人积累"**：随时增加、只对这台机器有意义、还可能写错要改。

混在一起的话，模型每写一条经验都要改动仓库文件，既脏又容易和别人的改动冲突。

## 二、目录结构

```
~/.thinker/projects/D--code-thinker/memory/
├── MEMORY.md                          ← 索引，一行一条
├── user-prefers-conda.md              ← 一条记忆一个文件
└── project-tests-must-run-offline.md
```

目录名由项目绝对路径算出：把 `:` `\` `/` 全换成 `-`。

```
D:\code\thinker  →  D--code-thinker
```

为什么不用哈希：哈希能保证唯一，但目录名变成乱码，用户想手动翻记忆时分不清哪个文件夹对应哪个项目。**可读性在这里比唯一性重要**——路径本身已经足够唯一了。（Claude Code 用同一套规则：`C:\Users\Jarvis` → `C--Users-Jarvis`）

## 三、只注入索引，这是关键设计

记忆会越攒越多。全量注入的话，攒到 50 条就把上下文吃掉了，而其中 90% 和当前任务无关。

所以启动时只给索引（每条一行标题 + 一句话说明），模型扫一眼就知道"有没有相关的"，需要细节时再用 `file_read` 去读那**一个**文件。

上限照抄 Claude Code：索引最多 200 行 / 25000 字符。超过就截断，并明确写一句"索引已截断，完整内容请读 xxx"——否则模型会以为记忆就这么点，重复记录已经存在的内容。

## 四、权限：本轮唯一主动放宽的地方

这是能不能用的分水岭。模型每记一条就弹一次"是否执行 file_write"，对话节奏会被打断得没法用。

要放行**两处**，少一处都不行：

| 位置 | 原来 | 为什么必须改 |
|---|---|---|
| `tools/file_tools.py` 的 `_within_workspace` | 只允许工作区内 | 记忆目录在 `~/.thinker` 下，天生越界，模型写不进去 |
| `core/permissions.py` 的 `classify` | file_write/file_edit 一律要问 | 每记一条弹一次窗 |

放行的范围刻意做得很窄：

```python
if tool_name in _MEMORY_TOOLS and is_memory_path(args.get("path")):
    return Decision(False, "low", "")
```

- `_MEMORY_TOOLS` 只有 `file_read` / `file_write` / `file_edit`，不含 glob/grep——模型要知道有哪些记忆，读索引就够了
- `is_memory_path` 会先 `resolve()` 再按**路径段**比较，`memory` 和 `memory-other` 不会误判
- 换成工作区里任何一个别的文件都不生效

测试里专门有一组"不该放行的绝不放行"：工作区内的普通文件、工作区外、缺 path 参数、同名前缀的邻居目录，全部仍然是 `need_approval=True`。

## 五、提示词：告诉模型"什么时候该记"

这部分最难，也最容易被写成正确的废话。实际写进系统提示词的是四组规则：

**该记**：用户纠正了你的做法且下次还适用、用户透露了代码里看不出来的偏好、你踩了坑并查清原因、项目有非显然的约定

**不该记**：看一眼代码就知道的事、一次性的临时状态、用户的提问本身、没把握的猜测

**怎么写**：一条一个文件（kebab-case 命名）、frontmatter 写 `name/description/type`、正文写"是什么 + 为什么 + 怎么用"、写完在 `MEMORY.md` 加一行索引、写之前先读索引避免重复

**频率**：完成一个任务后统一写，一轮对话 0~2 条是正常量。**写 5 条以上说明标准太松了**——这句是防止模型把每句话都当经验记下来，那样记忆会迅速退化成一堆噪音。

`type` 分四种（照 Claude Code）：`user` 身份背景 / `feedback` 纠正与确认 / `project` 项目决策 / `reference` 外部资源位置。

## 六、系统提示词的最终结构

```
## 语气与风格     ← 第 0 段：身份、安全底线（238 字符处）
## 记忆           ← 第 1 段：什么时候该记、怎么写（2139）
## 项目记忆        ← 第 2 段：THINKER.md 全文（2806）
## 你的记忆        ← 第 3 段：MEMORY.md 索引 + 使用说明（5418）
当前工作目录      ← 第 4 段：环境信息（5713）
```

总长 5832 字符。顺序的道理：规矩最先立住，环境放最后便于引用，两套记忆夹在中间。

## 八、遗留

| 编号 | 问题 | 计划 |
|---|---|---|
| A1 | 没有 `/memory` 命令，用户看不了模型记了什么 | 第 13 轮斜杠命令，先给 `thinker --memory` 也行 |
| A2 | 索引靠模型自己维护，它可能忘记更新 | 可靠做法是程序在写入后校验索引，但模型用的是通用 file_write，程序不知道写了什么 |
| A3 | 没有自动清理 | 到 50 条只提示合并，删除靠模型或用户手动 |
| A4 | 记忆不跨机器同步 | 和 Claude Code 一样，这是有意的（本机经验，换机器没有意义） |
| A5 | 子 agent 共享主 agent 的记忆 | 目前没隔离，子 agent 写记忆会污染主记忆；影响很小，暂不处理 |
