## 一、为什么先做这两件事

前 7 轮把稳定性、压缩、上下文成本乃至终端视觉都收拾干净了（第 7 轮刚把界面全面对齐 Claude Code），但"模型怎么改文件"这件事一直没解决。本轮之前有四处互相矛盾的地方：

| 编号 | 现象 | 出处 |
|---|---|---|
| A1 | 内置工具只有 4 个，唯一能干活的手是 `cmd_runner` | `tool_manager.py` 登记处 |
| A2 | `cmd_runner` 说明书教 `cat -n` / `sed -i` / `grep`，但环境是 Windows、命令走 `cmd.exe`，这三个命令默认不存在 | `cmd_runner.py` 说明书 + `enviroment.py` 的"操作系统：windows" |
| A3 | 子 agent 人设让它"用 Grep / Glob / Read"，工具清单里却没有这三个名字，派活基本必失败 | `subagent_manager.py` 人设 |
| A4 | 主循环自己调自己，每用一次工具、每等一次输入，调用栈厚一层 | `conversation.py` 两处递归 |

A1~A3 是"能不能可靠改文件"，A4 是"能不能把长任务跑完"。两者都是地基：权限规则、项目记忆、会话恢复、子 agent 并行，全都得站在它们上面。

顺带说一句，A1 其实是原作者自己留的待办——`cmd_runner.py` 里那行 `TODO: Read and Edit file will separate as serval tools`，本轮把它完成了（标记保留，记录来由）。

## 二、文件工具集

### 2.1 五个工具

新建 `src/tools/file_tools.py`。五个类写在同一个文件里，是因为它们共用路径边界、编码探测、忽略目录和"已读文件"记录，拆五份会把公共逻辑抄五遍。

| 工具 | 作用 | 关键约束 |
|---|---|---|
| `file_read` | 带行号读文件，`offset` / `limit` 分段 | 最多 2000 行；单行超 2000 字符截断并说明；空文件、二进制、目录都给明确提示 |
| `file_write` | 新建或整体覆盖文件 | 父目录必须存在；覆盖已有文件前必须先 `file_read` |
| `file_edit` | 精确替换 `old_string` → `new_string`，返回 unified diff | 必须先读；`old_string` 默认要唯一；支持 `replace_all` |
| `file_glob` | 按文件名通配符找文件，按修改时间倒序 | 支持 `**`；跳过 `.git` / `__pycache__` 等；最多 100 条 |
| `file_grep` | 按内容搜索，输出 `路径:行号:内容` | Python 正则实现，不依赖系统 grep；`include` 过滤；最多 100 处 |

全部继承 `BaseTool`，实现 `act()` / `json_schema()` / `get_status()`，和现有工具完全一致的接法。`ToolManager` 里放在最后登记（沿用"越重要越靠后"的注释约定），实测工具表从 4 个变成 9 个：

```
['smart_context_cropper', 'todo_write', 'task', 'cmd_runner',
 'file_read', 'file_write', 'file_edit', 'file_glob', 'file_grep']
```

### 2.2 两个安全设计

**路径边界**：`_resolve_path()` 把路径统一成绝对路径，用 `relative_to()` 判断是否还在工作区内（不用 `startswith`，否则 `D:/code/claude-other` 会被误判成内部）。越界返回中文提示；确需访问外部时设 `QUICKSTAR_ALLOW_OUTSIDE=1`。

**先读后写 + 过期检测**：`_read_files` 记的是"读到的内容 SHA1"，不只是路径。

```python
# file_edit 里的两道门禁
if str(resolved) not in _read_files:
    return "修改文件之前，必须先用 file_read 读过它。..."
if _sha1(text) != _read_files[str(resolved)]:
    return "文件在你读取之后被改动过，为防覆盖新内容已拒绝修改。..."
```

第二道是防止模型拿"记忆里的旧内容"覆盖磁盘上的新内容。写完后会更新指纹，所以"写完接着 edit"不会被误拦（测试里专门验了这条）。

### 2.3 真机调试抓到的一个真实 bug：CRLF 双重回车

第一次跑测试时，`test_edit_stale_and_replace_all` 挂了。追下去发现是 Windows 换行转换：

```
# 改前（直接用 path.write_text）
读取：read_bytes + decode  →  "x\r\nx\r\nx\r\n"
写回：write_text           →  每个 \n 又被转成 \r\n
结果：磁盘变成              "y\r\r\ny\r\r\ny\r\r\n"   ← 凭空多出空行
```

改法是新增 `_write_text()`，用 `newline=""` 关掉转换：

```python
# 改后
with path.open("w", encoding="utf-8", newline="") as f:
    f.write(text)
```

同时补了**跨行换行适配**：模型从带行号输出里抄来的 `old_string` 用 `\n`，而 CRLF 文件里是 `\r\n`，直接匹配会一处都找不到。现在先按原文找，找不到就把两边的 `\n` 都换成 `\r\n` 再试一次，替换后仍保持原文件的换行风格。

```
实测：CRLF 文件 "line1\r\nline2\r\n" 经跨行替换后 = b"first\r\nsecond\r\n"，无 \r\r\n
```

### 2.4 提示词一并改掉（不然新工具不会被用）

工具加进清单还不够，模型会凭习惯继续调 `cmd_runner`。本轮改了三处：

| 文件 | 改前 | 改后 |
|---|---|---|
| `tools/cmd_runner.py` | 说明书第 3/4 节教 `cat -n` / `sed -i` / `grep`，末尾附一句"Windows 上请用等价命令" | 开头列出 5 个专用工具及各自用途，明确"不要用 shell 拼文件操作"；保留 git 提交 / PR 规范不变 |
| `tools/subagent/subagent_manager.py` | "大范围搜索时用 Grep 或 Glob；已经知道具体路径时用 Read" | 改成 `file_glob` / `file_grep` / `file_read`，并补一条修改文件的规则 |

## 三、主循环去递归

### 3.1 改前

```python
async def _recursive_message_handling(self):
    ...
    if 有工具调用:
        await self._recursive_message_handling()   # 递归 +1 层
    else:
        ...
        await self._recursive_message_handling()   # 递归 +1 层
```

一次工具调用 + 一轮用户输入至少加两层栈。本机实测 `sys.getrecursionlimit() = 1000`，长任务跑到几百轮就会 `RecursionError`；异常冒到 `start_conversation` 被兜成"发生系统错误"，整个对话直接结束。

### 3.2 改后

保留老方法名（`start_conversation` / `start_task` 都调它），把它变成驱动器，原来的方法体平移成 `_run_one_iteration()`，**缩进一行没动**，只把两处递归换成 `return True`：

```python
async def _recursive_message_handling(self):
    while True:
        should_continue = await self._run_one_iteration()
        if not should_continue:
            return

async def _run_one_iteration(self) -> bool:
    ...                       # 原来的主体，原样保留
    if 有工具调用:
        return True           # 交给外层再转一圈
    if self._task_depth > 0:
        return False          # 子 agent 交差，收尾
    return True               # 等完用户输入，再转一圈
```

好处有三个：改动面小（主体逻辑零改动）、异常照样往外冒（捕获语义不变）、子 agent 的 `return` 语义用 `False` 精确表达。

### 3.3 实测对比

| 写法 | 轮数 | 栈深度 | 结果 |
|---|---|---|---|
| 旧式异步递归（对照函数） | 1200 | 每层 +1 | `RecursionError`（上限 1000） |
| 本轮 while 驱动 | 600 | 14 层 → 14 层，波动 0 | 正常完成 |

对照用例写在 `test_conversation_loop.py` 里，不是描述，是真跑出来的。

## 四、顺带做的最小授权规则

新增 3 个只读工具后，如果读个文件也弹一次确认，几乎没法用。但完整的权限系统是第 9 轮的事，所以本轮只做一处最小改动：把"要不要问"收进一个函数。

```python
# 改前
need_user_approve = args.get('need_user_approve', True)

# 改后
need_user_approve = self._needs_user_approval(tool_call.function.name, args)

# 规则：① 模型显式写了 → 听它的（兼容 cmd_runner）
#       ② 没写、且属于 READ_ONLY_TOOLS → 不打断用户
#       ③ 其余一律要问（安全优先）
READ_ONLY_TOOLS = {"file_read", "file_glob", "file_grep", "todo_write"}
```

`smart_context_cropper` 故意不进清单——它会真的删聊天记录。写类工具（`file_write` / `file_edit` / `cmd_runner` / `task`）默认仍要确认，模型可以显式传 `false` 跳过。

**这一项只是过渡**：模型仍然可以自己把危险操作标成 `false`，规则化（白名单 / 黑名单 / 路径边界 / "不再询问"）放到第 9 轮。
