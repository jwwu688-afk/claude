# 第 18.6 轮：输入层两个现网问题（跨行退格 + 底部留白）

> 日期：2026-11-09
> 版本：0.9.1 → 0.9.2
> 触发：用户实测反馈两条——「输入到第二行后，第一行的字删不掉」、「光标只能贴在最后一行，滚轮没法让它到中间」
> 教训：**「一行」这个假设藏在输入层的每一处计算里，只改一处等于没改**

---

## 一、问题一：跨到第二行后，第一行删不掉

### 现象

输入内容超过一行宽度后，终端自动折行（软换行）。一直退格，删到第二行开头就卡住——
第一行最后一个字永远删不掉。

### 根因

`LineEditor` 的擦除是这么写的：

```python
self._write("\b \b" * width)   # 退格、写空格、再退格
```

**`\b` 在行首不会跨行**。光标停在第二行第 0 列时，退格指令被终端忽略（或原地不动），
所以那个字擦不到。

更根本的原因是：整个输入层**假设"输入只占一行"**。buffer 是一个连续字符串，
但屏幕上是两行——没有做过"字符下标 → 屏幕行列"的换算。

### 修法

新增一个纯换算函数：

```python
_cursor_rowcol(prompt, text, cursor, cols) -> (row, col)
```

按终端规则逐字符模拟（一个字符写不下就换行，中文占两列），算出光标在第几个可视行、第几列。

退格时判断**删除前后行号是否变化**：

```text
row_before > row_after  →  这次删除跨了可视行
                         →  \x1b[1A（上移一行）+ \x1b[{col}G（跳到目标列）+ 擦
否则                    →  照常擦一个字符
```

### 这里踩了一个坑，值得记住

第一版判据写的是「删除前光标在第 0 列就上移」。测试直接打脸：

```text
第二行只有 1 个字符时：删除前 (row=1, col=1)，删除后才回到 (row=0, col=10)
```

**删除前 col 是 1，不是 0**，条件永远不成立，bug 一个都没修掉。而纯函数测试全绿——
因为换算函数本身是对的，错的是调用处的判据。

所以补了端到端用例：真实按键序列跑 `readline`，数输出里 `\x1b[1A` 出现了几次。
两行占位跨 1 次、三行占位跨 2 次。这类"算得对但判得错"的 bug，只有端到端能抓住。

## 二、问题二：输入行只能贴在最后一行

### 现象

输入行永远在缓冲区最后一行。用户用滚轮往上翻看历史，光标滚出视口——看起来"光标没了"，
也没法让输入行停在屏幕中间。

### 为什么程序改不了这个

终端的视口永远跟着光标走。只要输入行在最后一行，任何写操作（包括逐字符重绘）
都会把视口拉回底部。想「滚上去还能看见光标」，唯一的办法是**别让输入行在最后一行**。

### 修法：底部留白

```text
... 历史输出 ...
> 输入行                    ← 光标在这里
（空白 1）
（空白 2）
```

实现只有两行：

```python
self._write("\n" * n)              # 光标下移 n 行
self._write("\x1b[{}A".format(n))  # 再移回来，空白就留在下方
```

`n` 取环境变量 `THINKER_INPUT_PADDING`，默认 2，设 0 可关。

**为什么这个方案成立**：留白之后，打字的重绘发生在中间行，光标不碰缓冲区最后一行，
视口就不会被拉回底部。用户滚上去 2 行，输入行正好在视口中间。

**代价（写进注释，免得以后当 bug 报）**：每轮输入多占 2 行。模型回复通常远长于 2 行，
空白会被输出吃掉；但某轮只有一行输出时会残留几行空白，屏幕利用率略降。
这是"能滚动"换来的空间成本，不是错乱。

**为什么不用保存/恢复光标（`\x1b[s`/`\x1b[u`）**：conhost 对这对指令支持不稳定；
而 `\x1b[NA` 已经在第 18.5 轮用一条命令实测过可用（`AAA` / `CCC` 两行，`BBB` 被覆盖）。

## 三、连带影响

`test_tab_completion.py` 有 1 条断言看"写出的第一个片段是不是提示符"。留白序列
（`\n\n\x1b[2A`）跑在提示符之前，这条就挂了。

修法**不是改断言、也不是改实现**，而是在该测试文件里把留白关掉：

```python
os.environ.setdefault("THINKER_INPUT_PADDING", "0")
```

理由：那个文件测的是补全逻辑，留白是另一件事，由 `test_line_wrap.py` 覆盖。
两件事分开测，比让一条断言同时承担两种职责更清楚。
