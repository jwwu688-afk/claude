## 二、界面改了什么

### 2.1 新增 `ui/theme.py`：把配色和符号收归一处

之前颜色散在七八个文件里，有的用 `print` 打 emoji，有的用 rich 打颜色，风格不统一。现在集中定义：

```text
ACCENT = "cyan"          # 强调色：只有一个
DIM    = "bright_black"  # 次要信息
BULLET = "⏺"             # 模型发言 / 工具调用
RESULT = "⎿"             # 结果转折
PROMPT = "❯"             # 输入提示符
CHECK_ON / CHECK_OFF / CHECK_RUN = "✔" / "◻" / "◼"
console = Console(theme=Theme({...}), highlight=False)
```

`highlight=False` 是为了关掉 rich 的自动高亮——它会把路径、数字染成花花绿绿的颜色，反而乱。

### 2.2 欢迎页：从字符画换成信息面板

**改前**（一堆渐变星星，占 6 行，但没告诉你用的是哪个模型）：

```
 ══════════════════════════════════════════════════
  ✦ ✦ ✦ ✦ ✦ ✧ ✧ ✧ ✧ ✧
              ★ Welcome to Thinker ★
  ✧ ✧ ✧ ✧ ✧ ✦ ✦ ✦ ✦ ✦
 ══════════════════════════════════════════════════
```

**改后**：

```
┌────────────────────────────────────────────────────────────────┐
│                                                                │
│  ✻ Thinker    CLI                                              │
│  Claude Code 复刻 · MCP 客户端版                                │
│                                                                │
│  模型  spark-x2.6                                               │
│  目录  …/code/thinker                                            │
│                                                                │
└────────────────────────────────────────────────────────────────┘
  回车发送 · Ctrl+C 退出 · 上下文 80% 自动压缩
```

设计要点：

- 边框用暗灰，不抢内容；只有名字用青色
- 多了「模型」和「目录」两行——之前跑起来根本不知道当前用的是哪个模型
- 路径过长时只保留最后两级（`_readable_dir`），避免把面板撑破
- 底部提示里的「80%」是从 `.env` 的 `COMPRESS_THRESHOLD` 算出来的，不是写死的

### 2.3 输入提示符：`Enter:` → 青色 `❯`

```
改前：  👤
       Enter: 
改后：  ❯ 
```

原来每次输入前都会单独打一个 👤 emoji，聊十几轮后屏幕上堆一排人头，很乱。现在用一个青色雪佛龙符号，颜色码直接写进 `input()` 的提示字符串（`input()` 只接受字符串，给不了 rich 对象）。

### 2.4 对话结构：⏺ 与 ⎿

这是 Claude Code 最有辨识度的地方，原来这里是 `🤖` 加一堆 `Successfully called tool: ...`。

```
改前：
🤖
模型的回答……
ℹ️ Preparing to call tool: cmd_runner, args: {'command': 'dir', 'timeout': 30}
✅ Successfully called tool: cmd_runner, args: {...}, result: 驱动器 D 中的卷是 Data...

改后：
⏺ 
  模型的回答……
⏺ cmd_runner(dir)
  ⎿  驱动器 D 中的卷是 Data ⏎ 卷的序列号是 6480-B43B ⏎ D:\code\thinker 的目录 ⏎ …（共 15 行）
  ⎿ 上下文 3.5% · 花费 $0
```

具体做法：

| 元素 | 实现 |
|---|---|
| 正文缩进 | `Padding(Markdown(content), (0, 0, 0, 2))`，让回答"挂在圆点下面" |
| 工具名 | 加粗，参数用暗色括起来 |
| 参数摘要 | 新增 `_args_preview()`：`cmd_runner` 只显示命令本身（`dir`），`task` 显示任务描述，`todo_write` 显示"N 项" |
| 结果预览 | 新增 `preview_lines(text, 3, 70)`：取前 3 行、每行截 70 字，用 `⏎` 表示换行 |
| 失败 | 整行变红（`✗`） |
| 状态行 | `⎿ 上下文 3.5% · 花费 $0`，暗灰，独占一行 |

**为什么参数摘要要特殊处理？** 直接打印字典是 `cmd_runner({'command': 'dir', 'timeout': 30})`，又长又难读。现在你一眼看到的是 `cmd_runner(dir)`，和你脑子里想的是同一件事。

## 三、测试中发现并修掉的问题

真机跑一遍，比看代码有用得多。三个问题都是跑起来才暴露的。

### 3.1 `dir` 输出中文全是乱码

```
改前：������ D �еľ��� Data  �������к��� 6480-B43B
```

**原因**：`_decode` 只尝试 `utf-8` 和 `locale.getpreferredencoding()`。而这个环境里系统默认编码也是 UTF-8，两个都失败，最后走到 `errors="replace"`，中文全变成 `�`。

**修复**（`tools/cmd_runner.py`）：把 `gbk` 显式加进候选列表，并且去重：

```text
candidates = ["utf-8", "gbk", locale.getpreferredencoding(False)]
for encoding in candidates:
    try:
        return raw.decode(encoding)
    except (UnicodeDecodeError, LookupError):
        continue
return raw.decode("utf-8", errors="replace")
```

### 3.2 状态行粘在正文末尾

```
改前：  我是 Claude Code，Anthropic 的命令行编程助手。      ⎿ 上下文 3.6% · 花费 $0
```

**原因**：rich 的 `Live` 停止后，光标停在最后一行末尾（没有换行符），紧跟着打印的状态行就接上去了。

**修复**（`display_manager.stop_stream_display`）：如果这一轮流式确实输出了文字，停掉之后补一个换行。

```text
had_content = bool(self._stream_buffer.strip())
self._live.stop()
if had_content:
    self._console.print()
```

### 3.3 纯工具调用时多一个空圆点

```
改前：
⏺                      ← 模型这一轮没说话，只调了工具，这里就空着
⏺ cmd_runner(dir)
```

**原因**：圆点是在流式开始前单独打印的，而模型"只调工具不说话"时，这段文字是空的。

**修复**：把圆点画进流式区域内部，用 `Live(get_renderable=...)` 每次刷新时动态生成：

```text
def _stream_renderable(self):
    if not self._stream_buffer:
        return Text("")     # 没文字就什么都不画
    return Group(
        Text(f"{BULLET} ", style="qs.accent"),
        Padding(Markdown(self._stream_buffer), (0, 0, 0, 2)),
    )
```

这样"有没有圆点"自动跟"有没有内容"绑定，不再需要手动判断。

### 3.4 顺带：工具结果不再折成一坨

原来结果超过 400 字就被折成一行，`dir` 的输出变成一大段没法读的长句。现在改成 `preview_lines`：取前 3 行，每行截 70 字，用 `⏎` 连接，末尾标注总行数。
