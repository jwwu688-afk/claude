# 第 24 轮：技能不再占用斜杠命令

> 日期：2026-11-11
> 版本：0.10.1（行为变更，建议发版时递增到 0.11.0）
> 触发：用户提出「技能我不想要手动调用，只要模型自己判断调用的时候调用」
> 教训：**两个东西看起来都叫"命令"，但一个不花钱、一个花钱，就不能并排放**

---

## 一、现象

第 21 轮把每个技能自动登记成 `/名字` 命令，本意是"用户想强制用某个技能时能直接敲"。
实际用起来的问题是：

- `/pdf a.pdf` 这种写法要用户自己记住"技能名当命令、参数跟在后面"，而**参数怎么传**
  在命令系统和 `skill` 工具里是两套语义；
- 更根本的是口径混了：`/help` 里并排列着 `/cost`（本地算完，不花钱）和 `/pdf`
  （把上千字正文当成你说的话发出去，按输入计费）。用户没有理由知道这两者不一样，
  只能在列表底下补一句"技能命令例外"，属于用文案补设计的洞。

用户的原话是"只要模型自己判断调用"——这本来就是 `skill` 工具在做的事，
斜杠命令只是一个重复入口。所以整个去掉。

## 二、改法

删除"把技能登记成命令"这条链路，而不是加开关：

| 删掉的东西 | 它原本的职责 |
|---|---|
| `register_skill_commands()` | 扫描技能表 → 逐条 `register(CommandSpec(...))` |
| `_make_skill_handler()` | 为每个技能造一条命令处理函数（读正文 → 塞进待发消息） |
| `_one_line_summary()` | 把技能描述压成命令表里的一行摘要 |
| `_skill_command_names` | 技能命令名字台账，reload 时按它整批撤销 |
| `builtin_command_names()` | 给技能查重名用（`REGISTRY` 减去技能命令） |
| `_reserved_command_names()` + reload 里的重名跳过 | 阻止技能名与内置命令重名 |

**为什么要"删干净"而不是加一个 `skills-as-commands: false` 开关**：
开关意味着两条路径都要长期维护、都要测试，而其中一条已经确认是错的方向。
项目里已经有过一次同类教训（21.1 砍掉"模型可见性"这一维）：
**多一维可见性就多一个"我明明配了却不生效"的排查方向**。

### 顺带修掉一个隐藏的坏行为

删掉重名检查之后，一个叫 `cost` 的技能**不再被静默拒载**。
改前它会因为"和内置 /cost 重名"而被跳过，而用户完全看不出为什么要跳过它——
技能文件本身没有任何问题。现在技能和命令是两个独立命名空间，同名也不冲突。

## 三、启动路径的变化

改前：`main.cli()` → `register_skill_commands()` → 扫两个技能目录（每个文件读前 4KB）。
改后：启动期**不碰技能目录**。技能表由 `SkillManager._ensure_scanned()` 懒加载，
第一次被查询时（`ToolManager` 初始化问"有几个技能"、用户敲 `/skills`）才扫。

好处：坏掉的技能文件不再挡在启动路径上，只在真正用到时以一行告警出现。
风险：如果哪天有人把 `count()` 里的 `_ensure_scanned()` 删了，技能会静默变成 0 个、
`skill` 工具也就不登记了——**这条依赖很隐晦，记在这里**。

## 四、字段兼容

`user-invocable` 和 `argument-hint` 两个 frontmatter 字段现在**保留解析但不再影响任何行为**。

为什么不删：
- 删了会让从别处拷来的技能（尤其 Claude Code 的）报"未知字段"；
- 它们本身无害，只是失去了服务对象。

为什么不加"该字段已废弃"的警告：
- 用户改不了别人的技能文件，提示也没用；
- 项目既定规则是"认得就读，不认得就丢"，不为废弃字段单独开一条告警通道。

## 六、验证（不调模型）

在临时目录造两个技能（`pdf` 和一个故意叫 `cost` 的），指向它重扫：

| 检查项 | 结果 |
|---|---|
| 两个技能都加载 | `['cost', 'pdf']` —— `cost` 不再被重名规则跳过 |
| 命令表有没有变 | **没变**：reload 前后 `REGISTRY` 的 key 集合完全相同 |
| 内置 `/cost` 有没有被顶掉 | 没有，仍是"本次会话的花费与缓存命中" |
| `pdf` 在不在命令表里 | 不在 |
| 正文能不能读 | 能，`load_body(spec, "a.pdf")` 正常渲染 |
| `/help` 输出 | 10 条内置命令，无技能行；尾部是"技能不占用斜杠命令…" |

另外全仓 grep 确认 `register_skill_commands` / `builtin_command_names` /
`_reserved_command_names` / `_skill_command_names` 只剩注释里提到（用于说明历史），无代码引用。
