# 第 15.1 轮：越界放行口径与提示词修正

> 日期：2026-11-08
> 版本：0.5.0 → 0.5.1
> 触发：用户问「为什么这里查找文件用的不是 file_grep 而是 cmd_runner」

---

## 一、起因：一次看起来很正常的搜索

用户在会话里说「查找一下我的简历在哪里」，模型执行的是：

```text
cmd_runner(powershell -NoProfile -Command "$roots = @('C:\Users\Jarvis\Desktop','D:\','C:\Users\Jarvis\Downloads','C:\Users\Jarvis\Documents'); foreach ($r in $roots) { Get-ChildItem -LiteralPath $r -Recurse -Force -File | Where-Object { $_.Name -like '*简历*' } }")
```

结果是对的——找到了 15 个同名文件。但**它是靠绕路才做对的**：
它违反了系统提示词里「按文件名找文件用 file_glob」和「文件操作不能超出工作区」两条规矩，
而它绕过去的方式（shell 命令）恰好是唯一能跨盘搜索的办法。

这种「违反规矩反而更管用」的情况最危险：模型没有动机改，问题会反复出现，
而且每一次都在悄悄地绕过安全边界。

---

## 二、查到的三层原因

### 1. 用户说的 file_grep 其实是 file_glob

`file_grep` 搜的是**文件内容**，并且主动跳过二进制文件和超过 1MB 的文件。
简历是 PDF，用 file_grep 搜「简历」两个字，哪怕文件就在工作区里也搜不出来。
按文件名找文件该用 `file_glob`。

### 2. 但 file_glob 同样被硬挡住

`file_tools.py` 里所有路径都要过 `_resolve_path()`：

```text
if not _within_workspace(path):
    return None, (f"路径超出工作区：{path}。当前工作区是 {WORKSPACE_ROOT}。"
                  "如需访问工作区外的文件，请设置环境变量 THINKER_ALLOW_OUTSIDE=1。")
```

`WORKSPACE_ROOT` 在 import 时固定成启动 cwd（`D:\code\thinker`），
而简历在 `C:\Users\Jarvis\Desktop` 和 `D:\google`，全在外面。
模型调 `file_glob(pattern="**/*简历*", path="C:\\Users\\Jarvis\\Desktop")`，
拿回来的只有一句"路径超出工作区"，一个文件名都没有。

三条路里，只有 cmd_runner 能走通。

### 3. 三个设计缺口

| 缺口 | 具体表现 |
|---|---|
| A 提示词给了条当场做不到的路 | 原提示词只说「请让用户先设置 THINKER_ALLOW_OUTSIDE=1」。而环境变量要重启才生效，模型没法中途让用户去设，于是绕路 |
| B 权限层和执行层说的不是一回事 | 实测 `classify("file_glob", {"path": "C:\\Users\\Jarvis\\Desktop"})` → 无需审批、非高危。分类器**完全不看路径**，权限层说"很安全直接跑"，执行层才说"越界" |
| C cmd_runner 没有任何工作区检查 | `grep WORKSPACE_ROOT src/tools/cmd_runner.py` 结果为空，它不设 cwd、不看绝对路径。工作区边界只对 5 个 file_* 有效，换个工具名就绕过去了 |

缺口 C 是最根本的：**这道边界在 shell 面前是软的。**

---

## 三、改了什么

### 1. 用户侧：`.env` 打开放行

```text
THINKER_ALLOW_OUTSIDE=1
```

`_allow_outside()` 是**每次调用时**读 `os.getenv`，所以改完重启即可，不用重装。

### 2. 提示词改写（`core/prompt/system_rule.py`）

改前只有一句：

```text
- 文件操作默认不能超出当前工作区；确实需要访问工作区外的文件时，请让用户先设置 THINKER_ALLOW_OUTSIDE=1
```

改后：

```text
- 文件工具（file_read / file_write / file_edit / file_glob / file_grep）默认只能操作工作区内的路径。
  如果它们返回「路径超出工作区」，说明用户没有放行：此时应当停下来说明情况，并告诉用户可以设置
  THINKER_ALLOW_OUTSIDE=1（写进 .env，重启 thinker 后生效），**不要改用 cmd_runner 拼 shell 命令绕过它**。
  放行之后，file_glob / file_grep / file_read 可以直接处理工作区外的路径。
  搜索工作区外时优先指定具体目录（例如 C:/Users/<用户名>/Desktop），不要从盘符根目录开始递归——那会很慢。
```

四处针对性修改：

| 改动 | 治的是 |
|---|---|
| 明确说出「路径超出工作区」这句原文 | 模型能一眼认出这是"没放行"，而不是"路径写错了" |
| **不要改用 cmd_runner 绕过** | 直接堵掉这次实际发生的行为 |
| 「放行之后可以直接处理工作区外的路径」 | 治缺口 A：开着的时候模型不该再犹豫 |
| 「优先指定具体目录，不要从盘符根目录递归」 | 上次那条命令扫了 `D:\` 全盘，慢且容易误伤 |

### 3. 测试基准改为自证（`test/test_file_tools.py`）

本文件有两个用例（`test_read_errors`、`test_workspace_boundary_switch`）都断言
"工作区外路径必须被拒绝"。这只有在 `THINKER_ALLOW_OUTSIDE` 不存在时成立。

改前它们直接这么断言，等于**假设运行环境恰好干净**。这个假设有三个破法：

1. 用户照提示把 `THINKER_ALLOW_OUTSIDE=1` 写进了 `.env`；
2. 本文件将来 import 了 `Conversation`，连带触发 `api_client` 模块级的 `load_dotenv()`；
3. 用户在 shell 里 export 过。

实测第 1 种：`THINKER_ALLOW_OUTSIDE=1 python test/test_file_tools.py` → 挂 3/16，
报错是「文件不存在」——**完全指向不了真正原因**，排查时极容易怀疑到 `_within_workspace` 头上。

改法：在 `run_all_tests()` 入口统一 `pop` 掉这个变量，`finally` 里按原值还原；
`test_workspace_boundary_switch` 里保留一次 `pop` 作为二次保险（防单跑）。
测试的前提必须由测试自己保证，不能靠环境碰巧干净。

### 4. `.env.example` 对齐

- 补上 `THINKER_ALLOW_OUTSIDE=`（提示词现在明确引用了它，模板里却没有，新克隆的人没法发现）
- `MAX_TOOL_OUTPUT_CHARS` 从 `12000` 改成 `30000`

第二项是顺手修的旧问题：12000 低于 `file_read` 一次 2000 行的正常体量（约 3~6 万字符），
会让一次正常读文件被腰斩、模型反复带 offset 重读，反而更贵。
`core/limits.py` 的默认值和注释都写着"兜底上限必须 ≥ 业务上限"，模板却和它不一致。

## 四、验证

| 项 | 结果 |
|---|---|
| `.env` 加载后 `_allow_outside()` | `True` |
| `_resolve_path("C:\Users\Jarvis\Desktop")` | 放行（改前：`路径超出工作区`） |
| `_resolve_path("D:\google")` / `("C:\Windows")` | 放行 |
| 工作区内相对路径 `src` | 仍正常解析 |
| `file_glob(pattern="*简历*", path="C:\Users\Jarvis\Desktop")` | 找到 `我的简历.pdf` |
| 系统提示词渲染 | 改动正确进到发给模型的内容里 |
| `test_file_tools`（环境变量不设置 / `=1` / `=0` 三种） | 均 16/16 |
| 其余 14 个离线脚本 | 全绿 |
| 模型调用 | **0 次** |

「`=1` 也能过」这一条正是本轮修测试的直接证据——改前必挂。

## 五、遗留

**缺口 C 没修。** `cmd_runner` 仍然能拿命令扫任意路径，`THINKER_ALLOW_OUTSIDE`
管不到它（它管的是 file_* 五件套）。本轮只是让模型**没有动机**再绕路，
而不是让绕路**不可能**。

真要堵，需要两步，建议放进单独一轮：

1. 把越界判定提到 `classify()`，让权限层和执行层说同一句话（治缺口 B）；
2. 给 `cmd_runner` 加检查：命令里出现工作区外的绝对路径就要求审批（治缺口 C）。

注意第 2 步会误伤正常用法——`git` 操作、`pip install`、跑测试都可能带外面的路径，
需要先定好白名单，不能一刀切。

**一个附带观测**：模型在上一轮对话里还执行过
`copy ... & del /f "C:\Users\Jarvis\Desktop\我的简历.pdf"`（用户要求删简历）。
`classify()` 对它的判定是「审批=是、高危=是」，用户也确实拒绝了，这条链是好的。
但它说明一件事：模型自己填的 `need_user_approve: false` 完全不起作用（第 9 轮的设计），
真正把关的是 `classify()` 的命令正则。以后往 `classify()` 里加规则时，
要记得考虑 `&`、`&&`、`;` 串联多条命令的情况——目前只匹配到 `del` 就足够拦住，
但如果哪天换了写法漏掉，后果是不可逆的。
