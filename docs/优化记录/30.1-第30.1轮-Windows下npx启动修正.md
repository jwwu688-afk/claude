# 第 30.1 轮：Windows 上 `npx` 起不来（`.cmd` 扩展名）

> 日期：2026-11-12
> 版本：0.10.2（未动版本号）
> 触发：准备用 `thinker mcp add 12306 -- npx -y 12306-mcp` 试一个 npm 上的 MCP，先确认它到底能不能被拉起来
> 教训：**"配置写对了"和"进程能起来"是两件事；Windows 上裸命令只自动补 `.exe`**

---

## 一、现象

配置一字不差：

```json
{ "type": "stdio", "command": "npx", "args": ["-y", "12306-mcp"] }
```

启动后 `/mcp` 显示：

```text
✗ 12306 · 连接失败 · FileNotFoundError: [WinError 2] 系统找不到指定的文件。
```

同样的命令在 PowerShell 里手敲没问题——因为 PowerShell 自己会按 PATHEXT 找 `npx.cmd`，而 `CreateProcess` 不会。

## 二、根因

实测（用 thinker 的 Python，不下载任何包）：

```text
asyncio.create_subprocess_exec("npx", "-v")      → FileNotFoundError [WinError 2]
asyncio.create_subprocess_exec("npx.cmd", "-v")  → 10.9.7
```

- npm 在 Windows 上装出来的是 `npx.cmd`（外加 `npx.ps1`），**没有 `npx.exe`**；
- `CreateProcess` 对不带扩展名的命令只尝试追加 `.exe`；
- 所以 mcp SDK 的 `stdio_client` 一调 `anyio.open_process(["npx", ...])` 就失败。

这台机器上 npx 还不在系统 node 目录，而在 WorkBuddy 自带的 node 里：
`C:\Users\Jarvis\.workbuddy\binaries\node\versions\22.22.2-6\npx.CMD`。这更说明不能靠"用户手敲时能用"来判断。

## 三、改法

`client.py` 新增模块级函数，启动前解析：

```python
def resolve_command(command: str) -> str:
    return shutil.which(command) or command
```

- `which("npx")` → `C:\...\node\...\npx.CMD`（按 PATHEXT 找全了扩展名）；
- 实测 `anyio.open_process([<这个路径>, "-v"])` 能正常拉起；
- **解析不到就原样返回**，不在这里报错：可能是路径写错，也可能是"还没装、装完再启动"。让启动时的真实异常暴露出来，那一层的报错能看到实际命令行。

调用点只有一处：`_connect_all` 里构造 `StdioServerParameters` 时 `command=resolve_command(server.command)`。

## 四、为什么不在 `add` 时就把绝对路径写进 JSON

- 配置文件是**可移植**的：写死 `C:\Users\Jarvis\...\npx.CMD` 之后，换机器、换 node 版本、换用户就废了；
- 而裸 `npx` 在每台机器上都能被 `which` 解析到当次真实位置；
- 所以"配置存裸名、启动时解析"是唯一既能跨机器又能跑的组合。

## 五、验证

- `test_mcp_status.py` 新增 3 条：绝对路径原样返回、不存在的路径原样返回、Windows 上 `npx` 解析成存在的 `.cmd`；
- 真实连接回归：weather / calculator 仍正常连上（`已连接: ['weather', 'calculator'] | 失败: {}`）；
- 全部测试：`test_mcp_status.py` 23/23、`test_mcp_cli.py` 49/49、`test_compress_boundary.py` 37/37。

## 六、没做

- **没有真的把 `12306-mcp` 拉下来跑**。那会下载 npm 包，属于用户环境里的副作用，不该由一次排查顺手做掉。已验证到"子进程能被拉起"这一层，剩下的 `initialize` 握手要用户自己启动时看 `/mcp`。
- **没有改 `add` 的 `command` 校验**。现在仍然只提醒"PATH 里没找到"，因为解析发生在运行时，写进文件的应该是裸名。
