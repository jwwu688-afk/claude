# 第 18.5 轮：等待动画重做（光标 + 动态感）

> 日期：2026-11-09
> 版本：0.9.0 → 0.9.1
> 触发：用户反馈「模型思考的时候，光标显示位置不太正确」
> 教训：**为了让动画不残影而补的空格，会把光标推到很远的地方——补齐和光标位置是一对矛盾**

---

## 一、现象

等待模型回复时，那一行是这样的：

```text
⠋ 正在思考… (3s)                     █
```

文字只占十几列，光标却停在右边很远的地方（第 28 列），一闪一闪。
看起来像"光标位置错了"，实际是补齐空格的副产物。

## 二、根因

`_spin_loop` 每帧都要把整行补到固定宽度（`_SPINNER_CELLS = 28`）：

```python
sys.stdout.write("\r" + line + " " * pad + "\x1b[K")
```

**为什么非要补齐**：秒数从 `(9s)` 变 `(10s)` 会多一列。如果这一帧比上一帧短，
右边就会留下上一帧的残影（第 10 轮踩过，表现为"同一句话重复显示"）。

**代价**：补齐出来的空格确实写到了终端上，光标自然停在最后一个空格之后。
单行 spinner 的场景里，这个位置离文字很远。

## 三、修法：等待期间隐藏光标

```text
第一帧之前   → \x1b[?25l   （藏）
停止/异常时  → \x1b[?25h   （还）
```

隐藏之后视觉焦点落在转轮上，补齐的空格不可见——这是所有 CLI spinner 的通行做法。

**恢复做了三层，少一层就可能把终端的光标永久藏起来**：

| 位置 | 覆盖什么 |
|---|---|
| `_spin_loop` 的 `finally` | 线程正常退出、线程内部抛异常 |
| `_stop_spinner` 擦行时 | 主流程主动停止（并且让光标立刻回来，不等线程调度） |
| `atexit` 注册的兜底 | Ctrl+C / 未捕获异常导致进程退出（daemon 线程会被直接杀掉，`finally` 不保证执行） |

第三条是最容易漏的：正常跑一千次都不会出问题，只在异常退出时把用户终端搞成
"没有光标"，然后他得 `reset` 或者重开窗口。

## 四、动态感：三个周期错开

原来只有"转轮 + 秒数"，转轮 0.8 秒一圈，秒数 1 秒跳一次——看久了像卡住。

现在叠了三个不同周期：

| 元素 | 周期 | 效果 |
|---|---|---|
| 转轮（盲文点，8 帧） | 0.1 秒/帧，0.8 秒一圈 | 一直在转 |
| 省略号（0~3 个点） | 0.5 秒/格，2 秒一循环 | 呼吸感 |
| 动词（5 个词） | 3 秒/个，15 秒一循环 | "还在干活"的证据 |

三个周期互质，整帧不会在短时间内重复，看起来是连续的动，而不是一张图在闪。

```text
⠋ 正在思考 (0s)
⠼ 正在思考. (0s)
⠇ 正在思考.. (1s)
⠸ 正在思考. (2s)
⠼ 正在分析.. (3s)
```

为什么动词选这几个：都是中性的"在干活"，不带承诺（不说"马上好"），
也不会因为任务类型不同而驴唇不对马嘴。

## 五、可测性：把"算帧"抽出来

`_spin_loop` 跑在后台线程里、直接写 stdout，端到端几乎没法断言。
所以抽了一个纯函数：

```python
build_spinner_frame(elapsed) -> (plain, styled)
```

`plain` 是不带转义码的版本，专门用来算显示宽度（`cell_len` 会忽略 ANSI 的干扰，
但中文算 2 列，只有拿纯文本算才准）；`styled` 是真正写进终端的版本。

`test/test_spinner_frame.py` 6 条：

| 断言 | 为什么值得测 |
|---|---|
| 帧字符来自 `theme.SPIN_FRAMES` | 防止某处硬编码一帧，转轮"不转" |
| 动词每 3 秒换、15 秒一轮回 | 周期写错会表现为"偶尔卡住"，肉眼难发现 |
| 省略号 0→1→2→3→0 | 同上，且点号会干扰秒数的括号，要单独数 |
| 任意时刻宽度 ≤ 28 | 超了会自动换行，把后面所有输出顶乱 |
| `plain` 里没有 ANSI | 混进转义码会让 pad 算小，残影复发 |
| 同一时刻两次调用结果相同 | 后台每 100ms 算一次，依赖"上次状态"会跳帧 |

采样覆盖 0 秒到 1 小时（秒数 1→2→3→4 位的所有进位点）。
